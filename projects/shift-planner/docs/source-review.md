# 学生版から公開版への発展

公開版は、学生が提出した「出勤可能日と必要人数に基づくアルバイトシフト自動作成プログラム」をもとにしています。学生の元提出版と、教員が公開用に整理・改良したこの版は、別の版として扱います。

確認した元HTMLのSHA-256は次のとおりです。元提出ファイルと匿名化済みの学生配布版で一致することを確認しています。

```text
6d69ae43208a7b13e0fe59f20189241bb8553a690a3420f90addaf64047afd64
```

## 引き継いだ考え方と変更点

| 学生版の処理・機能 | 公開版での扱い |
| --- | --- |
| `timeToMin`・`fmtTime`による時刻と分数の変換 | 元の処理をもとに時刻の検証・表示へ使用 |
| スタッフ、出勤可能時間、必要シフト枠を別々に持つ構造 | 日付付きの枠と、スタッフID・枠IDの組み合わせへ発展 |
| 時間帯の重複と週の勤務上限日数の検査 | 必須条件として引き継ぎ、休息、連勤、時間上下限、スキル、固定担当を追加 |
| 勤務日数と勤務時間による候補の優先順位 | 勤務時間を基準に、勤務量の比率と過去実績を含む評価へ変更 |
| 勤務表と個人別集計 | 日付ごとの勤務表と、今回・過去・合計の時間集計へ発展 |
| Excelの複数シート出力 | 入力表と完成シフト・勤務集計の出力を引き継ぎ、CSV・Excel入力も追加 |

学生版は曜日順に枠を処理し、その時点で勤務量が少ない人から割り当てる方式でした。一度決めた割り当てを戻さないため、組み替えれば全枠を満たせる場合にも不足が生じます。

たとえば、Aは月曜と火曜に勤務可能、Bは月曜だけ勤務可能で、両者の上限が週1日、月曜・火曜に各1人必要とします。月曜にAを選ぶと火曜が不足しますが、月曜をB、火曜をAにすれば作成できます。

公開版では、候補を絞り、割り当てを進め、行き詰まったら戻って組み替える探索へ変更しました。完成した案には、入力とは独立した検証を再度行います。必要人数を満たさない途中の割り当ては出力しません。

## 配分の評価方法

必須条件を満たす案の中で、スタッフごとの勤務時間が、勤務量の比率で定めた目標時間へ近付くように評価します。過去実績を含める設定では過去と今回の合計を、含めない設定では今回分を評価します。同じ配分評価の案では、希望する枠への割り当ても比較します。目標は「全員の対象時間の合計 × その人の比率 ÷ 比率の合計」です。各人について「実際の対象時間と目標の差の二乗 ÷ 比率」を足し、その値が小さい案を選びます。勤務枠が細かく分けられない場合などには差が残ります。

必須条件のため目標時間に一致できない場合があります。また、制限時間に達した時点で案が見つかっていても、これ以上よい案がないと確認できていなければ最適とは表示しません。案が見つからずに時間切れになった場合も、不可能と断定しません。

たとえば、A：B＝2：1で、過去の勤務がAは8時間、Bは0時間、今回必要な勤務が16時間分なら、評価対象の合計は24時間です。合計の目標はAが16時間、Bが8時間なので、今回の目安はAもBも8時間になります。比率が同じでも、過去を含めるかどうかによって今回の割り当てが変わります。

## 全部を調べずに、よい案を探す工夫

枠の数が増えると、候補を組み合わせる数も増えます。6人から2人を選ぶ15通りを10枠で独立に組み合わせるだけで、`15^10 = 576,650,390,625`通りになります。これは条件適用前の例示であり、実際に調べる候補数や必要な処理時間の見積もりではありません。

探索では次の工夫を組み合わせています。

1. 固定担当を先に割り当て、固定同士や過去実績と必須条件の矛盾を検査します。
2. 各時点で、勤務可能日時や残りの勤務時間などから候補を絞り、選び方の組み合わせが少ない枠を優先します。
3. 行き詰まったら以前の選択へ戻り、別の組み合わせを試します。この処理がバックトラックです。
4. まだ割り当てていない枠を考慮し、「ここからどれだけ都合よく割り当てても、偏りをここまでしか減らせない」という評価の下限を求めます。今ある案を上回れない枝は省きます。同じ配分評価の場合には、希望枠への割り当て数の上限も比較します。

下限の計算の一部では、計算量が大きすぎない場合に、勤務枠の長さから共通の時間刻みを取り、勤務時間の上下限などを使った、条件を一部緩めた問題を利用します。元の問題より自由な問題でも改善できないなら、元の厳しい条件で改善することもできません。これは探索範囲を安全に省くための計算であり、利用者が指定した条件を実際の勤務表で緩める処理ではありません。

そのため「最良を確認」は、すべての候補を1つずつ生成したという意味ではありません。残る候補を省く根拠も含め、これ以上よい案がないと確認できたことを表します。

## 探索時間と結果の意味

画面の1・5・15・30秒は探索時間の上限です。最良であることを確認できれば早めに終了します。上限に達して条件を満たす案が残っていれば、その案を再検証して表示します。完成した案がなければ、未判定として勤務表を表示しません。

| 内部の状態 | 利用者へ伝える意味 |
| --- | --- |
| `optimal` | 条件を満たし、設定した配分評価と希望枠の優先順位で最良と確認できた |
| `feasible` | 条件を満たす案はあるが、探索上限のため最良かは未確認 |
| `infeasible` | 必須条件を同時に満たす案がないと確認できた |
| `unknown` | 探索上限などにより判定を終えられず、表示できる完成案もない |

入力形式の不備は、この4状態とは別に扱います。時間を延ばしても必須条件は緩まりません。作成不可能と確認できた入力には、条件の修正が必要です。計算はブラウザのWeb Workerで行い、画面操作と分けています。外部の計算サーバーやGPUを使う処理はありません。

## v1.1.0の操作上の発展

探索の評価方法を変えず、完成表の担当者を枠ごとに固定して再探索する操作と、スタッフ別に勤務表を絞り込む表示を追加しました。固定は必須条件の一つとして既存の検証へ渡します。表示の絞り込みは探索結果を変更せず、CSV・Excelは全員分、印刷は表示中の勤務表を対象にします。

ブラウザ画面には、必須条件と配分目標の違い、時間と回数の違い、学生版の順番による割り当てと組み替え探索の違いを学べる解説も加えました。

## 公開データと依存ライブラリ

公開デモは架空のスタッフID・表示名・勤務実績から作成しています。元提出資料の氏名、学籍番号、学科情報、実際の勤務データは含めません。利用者の入力やファイルはブラウザ内で処理します。

Excelを扱うライブラリはローカルファイルとして同梱し、バージョンと利用条件を [THIRD_PARTY_NOTICES.md](../THIRD_PARTY_NOTICES.md) に記載します。元版の外部CDNへの依存は、公開版の実行に必要ありません。
