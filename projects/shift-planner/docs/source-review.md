# 学生版から公開版への発展

公開版は学生が提出した「出勤可能日と必要人数に基づくアルバイトシフト自動作成プログラム」をもとにしています。元の提出版と教員が公開用に整理・改良した版は分けて扱います。

確認した元HTMLのSHA-256は次のとおりです。元提出ファイルと匿名化済みの学生配布版で一致しています。

```text
6d69ae43208a7b13e0fe59f20189241bb8553a690a3420f90addaf64047afd64
```

## 引き継いだ機能と変更点

| 学生版の処理・機能 | 公開版での扱い |
| --- | --- |
| `timeToMin`・`fmtTime`で時刻と分数を変換 | 元の処理をもとに時刻の検証と表示へ使用 |
| スタッフ・出勤可能時間・必要枠を分けて管理 | 日付付きの枠とスタッフID・枠IDの対応へ発展 |
| 時間の重複と週の勤務上限日数を検査 | 必須条件として継承。休息・連勤・時間上下限・役割・固定担当も追加 |
| 日数と時間で割り当ての優先順位を決定 | 合計時間を基準に比率と過去実績を含む評価へ変更 |
| 勤務表と個人別集計を表示 | 日付別の勤務表と今回・過去・合計時間の表示へ発展 |
| Excelを複数シートで出力 | 出力を継承してCSV・Excel入力も追加 |

学生版は曜日順に枠を処理します。その時点で勤務量が少ない人から割り当てる方式です。一度決めた担当を戻さないため組み替えれば満たせる条件でも不足する場合があります。

たとえばAは月曜と火曜に働けるものとします。Bが働けるのは月曜だけです。2人とも週1日が上限で各日1人ずつ必要なときに月曜をAにすると火曜が不足します。月曜をBに変えると火曜にAを配置できます。

公開版は行き詰まったときに前の選択へ戻って担当を組み替えます。完成した案には探索とは別の検査を行います。必要人数を満たさない途中の案は出力しません。

## 勤務時間の配分

通常の作成では必須条件を満たす案から勤務時間の偏りが小さいものを選びます。過去実績を含める設定では過去と今回の合計を評価します。含めない設定では今回分だけを評価します。

各スタッフの目標は次の式で求めます。

```text
目標時間 = 全員の対象時間の合計 × その人の比率 ÷ 比率の合計
```

各人について「実際の対象時間と目標の差の二乗 ÷ 比率」を求めて合計します。その値が小さい案を優先します。値が同じ場合は希望枠への割り当て数を比べます。

枠の長さや勤務可能日時によっては目標どおりになりません。比率はA：B＝2：1とします。過去の勤務はAが8時間でBは0時間です。今回16時間分を追加すると対象は合計24時間です。目標はAが16時間でBは8時間となるため今回は2人とも8時間ずつが目安になります。

## 探索の範囲を絞る工夫

6人から2人を選ぶ方法は15通りあります。10枠で独立に選ぶ単純計算では `15^10 = 576,650,390,625` 通りです。これは条件を考慮する前の例であり実際に調べる候補数や処理時間の見積もりではありません。

探索には次の工夫を使っています。

1. 固定担当を先に配置します。固定同士や過去実績と必須条件が両立するかも検査します。
2. 勤務可能日時や残りの勤務時間から候補を絞ります。選び方の組み合わせが少ない枠を優先します。
3. 行き詰まったら以前の選択へ戻って別の担当を試します。この処理がバックトラックです。
4. 途中の案が今ある案を上回れるか見積もります。上回れないと分かった枝は調べるのをやめます。

配分の見積もりには評価の下限を使います。残りを最も都合よく割り当てても今ある案を上回れない場合は探索を省けます。配分の評価が同じ場合は希望枠への割り当て数の上限も比べます。

下限の計算の一部では勤務枠の長さから共通の時間刻みを取ります。計算量が大きすぎない場合に勤務時間の上下限などを使った一部の条件だけの問題を解きます。元より自由な問題でも改善できないなら厳しい条件の元の問題でも改善できません。この計算は候補を安全に省くためのものです。出力する勤務表の必須条件を緩める処理ではありません。

「最良を確認」は全候補を1つずつ生成したという意味ではありません。調べる必要がないと判断できた候補も含めてこれ以上よい案がないと確認できた状態です。

## 探索時間と結果

画面の1・5・15・30秒は探索の上限です。最良の案を確認できれば早めに終了します。時間が尽きた場合も条件を満たす案があれば検証して表示します。完成案がなければ未判定と表示します。

| 内部の状態 | 意味 |
| --- | --- |
| `optimal` | 必須条件を満たす案があり設定した評価で最良と確認できた |
| `feasible` | 必須条件を満たす案はあるが最良かどうかは未確認 |
| `infeasible` | 必須条件を同時に満たす案がないと確認できた |
| `unknown` | 探索を終えられず表示できる完成案もない |

入力の不備はこの4状態とは別に扱います。時間を延ばしても必須条件は変えません。計算はブラウザのWeb Workerで行います。外部の計算サーバーやGPUを使う処理はありません。

## 担当固定とスタッフ別表示

v1.1.0では完成表の担当者を枠ごとに固定して再探索する操作を追加しました。固定は必須条件として検査します。スタッフ別に勤務表を絞る表示も追加しました。表示だけを切り替えるため探索結果は変更しません。CSV・Excelは全員分を出力し印刷は表示中の勤務表を対象にします。

ブラウザ画面には必須条件と配分目標の違いや時間を基準に配分する理由を説明しています。学生版の順番による割り当てと組み替え探索の違いも具体例で紹介しています。

## 欠勤時の代替案

v1.2.0では欠勤した日時を勤務不可にしたうえで元の担当をなるべく維持する探索を追加しました。元の勤務表を検証してから欠勤の条件を準備します。1日の欠勤はその日の全枠に適用します。特定の枠だけを指定することもできます。

代替案は次の順に比べます。

1. 担当を変更する枠数
2. 延べ交代人数（各枠の交代数の合計）
3. 既存の勤務時間の配分評価
4. 希望枠への割り当て数

変更枠数と交代数が少ない案を先に選びます。勤務時間の均等さは変更が同じ案の間で比較します。担当者の表示順だけが違う場合は変更に含めません。

「欠勤する人の固定だけ外す」を有効にした場合に限って該当する本人の固定を解除します。ほかの担当固定や時間の上下限などは維持します。欠勤で最低勤務時間を満たせなくなった場合も条件を勝手に変えません。

探索中の変更は元の入力から分けて保持します。代替案と変更内容を表示した後に利用者が採用するか判断します。採用すると欠勤日時の勤務不可設定と必要な固定解除を入力へ反映します。時間内に最良と確認できなければ変更が最小かどうかは未確認と伝えます。完成案がない場合は勤務表を出力しません。

## 公開データと依存ライブラリ

デモは架空のスタッフIDと表示名と勤務実績で作成しています。学生の氏名や学籍番号や学科情報は含めません。実際の勤務データも使いません。利用者の入力とファイルはブラウザ内で処理します。

Excel用ライブラリはローカルファイルとして同梱しています。バージョンと利用条件は [THIRD_PARTY_NOTICES.md](../THIRD_PARTY_NOTICES.md) に記載しています。元版の外部CDNは公開版の実行に必要ありません。
