# 測定値と推定値の読み方

この教材では、練習用のパスワードから作ったハッシュ値に候補を照合します。ハッシュ値は、入力から計算する照合用の値です。外部のアカウントへログインする実験ではありません。普段使っているパスワードは入力せず、自動生成やデモを使って試してください。

## 「見つかった」と「時間を推定した」は別です

| 表示 | 意味 |
| --- | --- |
| 発見・実測 | 実際に候補を計算し、一致を確認しました。 |
| 未発見・試行終了 | 今回の時間や件数の範囲では見つかりませんでした。安全だと証明したわけではありません。 |
| 推定 | 実測した処理速度と候補数から計算した目安です。その時間まで実行した結果ではありません。 |

辞書や規則を使う方法は、よくある単語や数字の並びを先に試します。短いリストで見つかる場合もあれば、リストに含まれず最後まで見つからない場合もあります。「今回最も早かった方法」は、用意した方法と候補の範囲での比較です。

## 推定時間に置いている条件

正解となる文字列の用意と、探す側の条件は独立しています。探索条件は入力や生成した正解の長さ・文字種から自動では取得しません。

| 探す側の条件 | 候補数N |
| --- | --- |
| 手がかりなし | 半角94種類を使い、1文字から指定上限L文字までの候補数 `94^1 + … + 94^L` |
| 文字種と文字数Lを指定 | 文字集合の大きさをAとして `A^L` |
| 文字種を指定し、文字数は不明 | 1文字から指定上限L文字までの候補数 `A^1 + … + A^L` |
| 文字の並び・一部を指定 | 位置ごとの文字集合の大きさを掛け合わせた数。既知の固定文字は1通り |

上限は今回の実験範囲で、正解の長さを知っているという意味ではありません。文字数が不明なら短い順に探索し、各方法の時間・件数の予算を全長で共有します。正解が指定した範囲の外にあっても、その情報を使って探索を省くことはありません。調べ終えた範囲で一致しなければ未発見となります。表示する推定時間は、範囲外の正解には当てはまりません。

**指定範囲の全候補が同じ確率で正解になる**と仮定すると、重複なく順に調べる平均の照合回数は `(N + 1) / 2`、最後まで調べる場合は `N` 回です。これを1秒あたりの処理件数で割って所要時間の目安にします。文字数が不明な場合、この仮定は「長さを一様に選び、その長さの文字列を生成する」とは異なります。人が考えた単語や規則的な文字列でも、この平均を実際の強さとして当てはめることはできません。

文字種による探索の推定には、探索上限の文字数で測った代表速度を使い、短い文字数でも同じ速度と仮定します。並びを指定した場合は、その並びの候補生成と照合を別に測定します。長時間の処理や別の端末でも同じ速度が続く保証はありません。

この実験では、照合用データを手元で何度でも計算できる状況を想定します。実際のログイン画面には試行回数の制限や多要素認証があります。反対に、より速い実装や複数の計算機を使えば、同じ照合を短時間で処理できる場合もあります。表示は、この端末と計算方式での目安です。

## SHA-256を使う理由と限界

SHA-256を1回計算する方式は、短い時間で「候補を作る → 計算する → 比べる」という流れを見るための実験です。ソルトという追加の値を付けても、1回の計算そのものが重くなるわけではありません。SHA-256を1回計算するだけの方式は、実際のパスワード保存には適しません。

実際の保存では、Argon2idやPBKDF2など、1回の照合に計算量をかける方式を使います。ソルトは、同じパスワードでも保存値を変え、使い回せる事前計算を防ぐためのものです。保存方式やその設定が変われば、同じパスワードでも推定時間が変わります。SHA-256の測定速度を、そのままArgon2idやPBKDF2の速度として使うことはできません。

長さを増やすことと、推測されにくい作り方を選ぶことの両方が大切です。文字種を増やしただけで安全と判断せず、使い回しを避け、多要素認証も活用してください。

## 元の学生作品と公開版の違い

提出作品の中心は、同じ計算をCPUとGPUで大量に処理する性能比較です。16進数の9・10・11桁を使っているため、候補数はそれぞれ `16^9`、`16^10`、`16^11` です。10進数の同じ桁数とは候補数が異なります。

元の `mix` 関数は、64ビット整数にXOR、シフト、乗算を行う変換です。XORと右シフトの組合せは元に戻せます。また、使っている2つの乗数は奇数なので、64ビットの範囲で乗算も元に戻せます。この関数は全体として効率よく逆計算でき、パスワード保存用の暗号学的ハッシュではありません。その探索速度から、実際のパスワードが何年安全かを判断することはできません。

| 比較の観点 | 読み取れること |
| --- | --- |
| CPUの1スレッド・2スレッド | 処理分担の効果と負担。「2スレッド」は、常に2コアを占有するという意味ではありません。 |
| NumPyとGPUカーネル | ハードウェアと実装を組み合わせた速度。元のCPU実装は配列生成と複数の演算を行い、GPU実装は1つのカーネルに演算をまとめています。 |
| 同じ件数の計算 | 正解の位置に左右されにくい処理速度の比較。コンパイルや初回準備の扱いもそろえて読みます。 |
| 正解までの探索 | 候補を調べる順番と正解の位置も含めた所要時間。最後のバッチには、発見後の候補の計算が含まれる場合があります。 |

公開版では元の整数変換をSHA-256の照合に置き換えています。「手がかりなし」と「文字の種類・文字数を指定」では、ColabはPython・Numba・Numba並列・GPUで同じ候補範囲を測り、ブラウザ版はCPUと任意のWebGPUを使います。「文字の並び・一部を指定」は位置ごとに異なる候補集合をCPUで列挙し、その候補列による速度を別に測ります。このモードではNumba・GPUとの比較を行いません。

両版とも辞書と規則は指定した探索範囲に合う候補だけを試します。並びを指定していない場合、並びの専用探索は行いません。辞書や規則のリストと実装は両版で異なるため、照合件数や発見結果が一致するとは限りません。Web版のSHA-256はソルトを付け、Colabの速度比較は単発のSHA-256を使います。端末や照合方式を越えて速度をそのまま流用しません。

Colabの結果ZIPには探索条件と集計結果を保存しますが、入力文字列・照合用ハッシュ・固定した先頭や末尾の文字・位置ごとの候補集合は含めません。Notebook自体の入力や画面出力は別に残る場合があります。

GPUが使えなくてもCPUで実験できます。WebGPUはブラウザと端末の対応状況によって使えず、利用可能な場合もソフトウェア実装が選ばれることがあります。利用できなかった場合のCPU測定を、GPUの実測として扱うことはありません。
