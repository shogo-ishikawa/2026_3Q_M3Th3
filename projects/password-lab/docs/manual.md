# 使い方

## Web版でまず試す

1. [ブラウザ版](https://shogo-ishikawa.github.io/2026_3Q_M3Th3/projects/password-lab/)を開き、最初の例のまま「試してみる」を押します。
2. どの探し方で見つかったか確認します。「単語＋数字」「ランダム12文字」でも比べてみましょう。
3. 慣れたら文字数や文字の種類を変え、生成した文字列で実験します。

**実際に使っているパスワードは入力せず、練習用だけを使ってください。** Web版の入力は端末内で処理し、送信・履歴保存を行いません。

### 入力と生成

空白を除く半角英数字・記号の1〜32文字を扱います。自動生成は「文字数」と使える種類を選び、「この条件で生成」を押します。各文字を選んだ集合から均等に選びます。選んだ全種類が必ず含まれる方式ではありません。

**文字列を作る条件と、探す側が使う情報は別に設定します。** 入力した正解から文字種や文字数を読み取り、探索条件へ自動で渡すことはありません。

### 探す側の情報を選ぶ

「探す側は、何を知っている？」で、次の3つから選びます。Web版とColab版で同じ考え方を使います。

| 選択 | 試す範囲 |
| --- | --- |
| 手がかりなし | 数字・大小英字・記号の94種類を使い、1文字から指定した上限まで短い順に探索 |
| 文字の種類・文字数を指定 | 探索に使う文字種を独立に選択。文字数も分かる場合はその長さだけ、不明なら1文字から指定した上限まで探索 |
| 文字の並び・一部を指定 | 分かっている先頭・末尾の文字と、間に入る文字の種類・個数を指定 |

「手がかりなし」の上限は、今回どこまで試すかという実験の範囲です。正解の文字数を表す値ではありません。例えば上限を6文字にすると、7文字以上は候補に入りません。正解が範囲の外でも、正解の中身を見て探索を省くことはありません。

並びを指定するときは、専用の記号を覚える必要はありません。次のように選択欄で組み立て、表示される「今回、試す範囲」を確認します。

| 探したい並び | 先頭 | 続く文字 | その次の文字 | 末尾 |
| --- | --- | --- | --- | --- |
| sakura＋数字4文字 | sakura | 数字・4文字 | 使わない・0文字 | 空欄 |
| 小文字4文字＋数字4文字 | 空欄 | 小文字・4文字 | 数字・4文字 | 空欄 |

固定する先頭・末尾は空欄でも構いません。文字グループは2つまで指定でき、数字・小文字・大文字・大小英字・英数字・記号・94種類すべてから選べます。使わないグループは0文字にします。指定した並び全体は1〜32文字に収めてください。

### 探索と結果

| 探し方 | 試す候補 |
| --- | --- |
| 教材用の辞書 | よくある文字列の小さなリスト |
| よくある規則 | 単語と数字・記号の組合せ、連番・繰り返しなど |
| 総当たり | 指定した文字種・文字数の範囲で、全組合せを順に列挙 |
| 並びの手がかりによる探索 | 「文字の並び・一部を指定」を選んだときだけ、その並びの全組合せを列挙 |

各方式は同じ照合用データに対して独立に実行します。辞書と規則も、指定した探索範囲に合う候補だけを試します。並びを指定した場合は、総当たりの代わりにその並びを探索します。選んだ時間か100万候補で止まり、「停止」でも中断できます。文字数が不明でも、時間・件数の上限は各方法の全体で共有します。

「発見」は候補を実際に計算して一致した結果です。「上限で停止」は未確認の候補が残っている状態、「リスト内に一致なし」は教材内の候補を調べ終えた状態です。予想した範囲や並びが正解と違えば、最後まで調べても見つかりません。辞書で見つからなくても、別の辞書で見つかる可能性があります。

Web版はCPUで照合速度を別に測り、総当たりの推定と長さの比較表に使います。条件を変えたら、もう一度「試してみる」を押してください。

### 照合方式とGPU

SHA-256は高速な照合を見るための教材です。PBKDF2は繰り返し計算で照合1回を重くします。Web版のPBKDF2-HMAC-SHA-256・1万回は、違いを体験するための設定であり、実用の推奨値ではありません。

「GPUでも総当たりを試す」をオンにすると、対応環境ではWebGPUで同じSHA-256候補を先頭から照合します。GPUで比較できるのは「手がかりなし」と「文字の種類・文字数を指定」です。並びを指定した探索とPBKDF2はCPUのみです。GPUが使えない場合もCPU結果を確認できます。

GPUは候補をまとめて計算するため、発見した候補より後の照合も同じ一括処理に含まれます。照合数は実際に処理した件数です。初回の準備・コンパイル・正答確認は探索時間から除きます。WebGPUのフォールバック実装は物理GPUの性能とは限りません。

## Colabでコードも試す

[Colab版](https://colab.research.google.com/github/shogo-ishikawa/2026_3Q_M3Th3/blob/main/projects/password-lab/password_lab.ipynb)を開き、セル1から5まで順に実行します。リンクからそのまま作業でき、編集内容を残す場合は「ドライブにコピーを保存」を選びます。

| セル | 操作 |
| --- | --- |
| 1：準備 | 必要なライブラリを準備します。GPUを使う場合はColabの「ランタイム → ランタイムのタイプを変更」でGPUを選び、`gpu_enabled`を有効にします。CPUだけでも続けられます。 |
| 2：文字列 | `source_mode`でデモ・自動生成・自分で入力を選びます。手入力は実行後の入力欄を使います。 |
| 3：探索と速度 | 探す側の情報と時間・件数の上限を指定します。探し方の結果と計算方法ごとの速度を表示します。 |
| 4：推定と保存方式 | 総当たりの推定時間と、同じ文字列によるSHA-256・PBKDF2の照合時間を確認します。 |
| 5：保存 | 実験条件と集計結果をCSV・JSON入りのZIPで保存します。 |

セル2は正解となる文字列を用意する操作です。セル3で探す側の情報を別に選びます。例えば数字4文字のデモでも「手がかりなし」なら94種類・1文字から上限まで探します。数字4文字だけで比べたい場合は、セル3で数字のみと既知の文字数4を指定してください。

辞書と単語の変形は、どの情報を選んでも指定した範囲内で試します。並びを指定したときだけ、その並びの専用探索が加わります。

「手がかりなし」と「文字の種類・文字数を指定」では、Python・Numba・Numba並列・利用可能なGPUを比較します。同じ候補範囲を3回ずつ全走査した中央値を使い、初回の変換・準備時間は別表示にします。総当たりには実測で最も速かった方式を使います。小さな問題では準備や分担の負担が大きく、並列化で遅くなる場合もあります。

並びを指定した場合は、その並びの候補を作り、Pythonの`hashlib`で照合する速度を別に測ります。辞書と単語の変形も`hashlib`で照合します。

総当たりはバッチ単位で計算します。発見後もそのバッチを最後まで処理するため、件数には余分な照合が含まれ、時間上限を少し超える場合があります。

結果ZIPには文字種・文字数などの探索条件と集計結果を保存します。入力文字列・照合用ハッシュ・先頭や末尾の固定文字・位置ごとの候補集合・探索候補そのものは含めません。ColabはGoogle上で動き、Notebookの入力や画面出力はZIPとは別に残る場合があります。共有前に確認してください。文字列を変える場合はセル2から実行し直します。

## 推定時間の読み方

使える文字がC種類なら、指定した探索範囲の候補数Nは次のように計算します。

| 探索範囲 | 候補数N |
| --- | --- |
| ちょうどL文字 | CのL乗 |
| 1文字からL文字 | Cの1乗＋Cの2乗＋…＋CのL乗 |
| 先頭・末尾と文字グループを指定 | 各位置で使える文字の種類数を掛け合わせる。固定文字の位置は1通り |

例えば「sakura＋数字4文字」は1万通り、「小文字4文字＋数字4文字」は26の4乗×10の4乗通りです。**範囲内の全候補が同じ確率で正解になる**と仮定し、速度r件/秒で探す場合の目安を表示します。

| 推定 | 計算 |
| --- | --- |
| 平均的に見つかるまで | (N + 1) ÷ (2 × r) 秒 |
| 全候補を調べるまで | N ÷ r 秒 |

これは指定した範囲内の見積もりです。正解が範囲の外にある場合の所要時間や、人が考えた単語・連番の安全性を表すものではありません。辞書や規則で先に見つかる例も一緒に見てください。「要注意」は教材内で短時間に発見できたという意味です。未発見や長い推定時間は安全の証明ではありません。

文字種による探索では、上限の文字数で測った代表速度を全体に仮定します。並びを指定した場合は、その候補列で測った速度を使います。速度は計算機・実装・端末の負荷・照合方式で変わります。SHA-256の実測速度をPBKDF2の探索時間へ流用することもできません。

### Web版とColab版の測定条件

| 項目 | Web版 | Colab版 |
| --- | --- | --- |
| SHA-256への入力 | 実験ごとの8文字ソルト＋候補 | 候補だけ |
| 辞書・規則の候補 | 指定した探索範囲に合うもの | 指定した探索範囲に合うもの。リストの内容はWeb版と異なる |
| PBKDF2の反復回数 | 1万回 | セル4で指定。初期値10万回 |
| 主な目的 | すぐ操作して、結果と長さの違いを体験 | コードを読み、探索方法と計算装置を比較 |

別の条件・実装なので、2つの時間の数字は直接比較しないでください。どちらのPBKDF2設定も実用の推奨値ではありません。

## 実際のサービスとの違い

この教材は保存済みの照合データを手元で何度でも試せる、オフラインの実験です。実サービスへのログインは行わず、試行回数の制限や多要素認証も含みません。表示は実サービスの突破時間ではありません。

元作品のCPU・GPU比較を引き継ぎ、照合を整数変換から実際のSHA-256に変更しています。単発のSHA-256は実用のパスワード保存方式ではありません。[詳しい前提と出典](model-notes.md)を参照してください。
