# 使い方

## Web版でまず試す

1. [ブラウザ版](https://shogo-ishikawa.github.io/2026_3Q_M3Th3/projects/password-lab/)を開き、最初の例のまま「試してみる」を押します。
2. どの探し方で見つかったか確認します。「単語＋数字」「ランダム12文字」でも比べてみましょう。
3. 慣れたら文字数や文字の種類を変え、生成した文字列で実験します。

**実際に使っているパスワードは入力せず、練習用だけを使ってください。** Web版の入力は端末内で処理し、送信・履歴保存を行いません。

### 入力と生成

空白を除く半角英数字・記号の1〜32文字を扱います。手入力では、含まれる文字種から探索用の集合を決めます。小文字が1文字でもあれば、小文字26種類を候補にします。

自動生成は「文字数」と使える種類を選び、「この条件で生成」を押します。各文字を選んだ集合から均等に選び、その集合を探索条件にも使います。選んだ全種類が必ず含まれる方式ではありません。

### 探索と結果

| 探し方 | 試す候補 |
| --- | --- |
| 教材用の辞書 | よくある文字列の小さなリスト |
| よくある規則 | 単語と数字・記号の組合せ、連番・繰り返しなど |
| 総当たり | 同じ長さ・文字集合の全組合せを順に列挙 |

各方式は同じ照合用データに対して独立に実行します。Web版では辞書と規則も今回の文字数・文字集合に合う候補だけを試します。選んだ時間か100万候補で止まり、「停止」でも中断できます。

「発見」は候補を実際に計算して一致した結果です。「上限で停止」は未確認の候補が残っている状態、「リスト内に一致なし」は教材内の候補を調べ終えた状態です。辞書で見つからなくても、別の辞書で見つかる可能性があります。

Web版はCPUで照合速度を別に測り、総当たりの推定と長さの比較表に使います。条件を変えたら、もう一度「試してみる」を押してください。

### 照合方式とGPU

SHA-256は高速な照合を見るための教材です。PBKDF2は繰り返し計算で照合1回を重くします。Web版のPBKDF2-HMAC-SHA-256・1万回は、違いを体験するための設定であり、実用の推奨値ではありません。

「GPUでも総当たりを試す」をオンにすると、対応環境ではWebGPUで同じSHA-256候補を先頭から照合します。PBKDF2はCPUのみです。GPUが使えない場合もCPU結果を確認できます。

GPUは候補をまとめて計算するため、発見した候補より後の照合も同じ一括処理に含まれます。照合数は実際に処理した件数です。初回の準備・コンパイル・正答確認は探索時間から除きます。WebGPUのフォールバック実装は物理GPUの性能とは限りません。

## Colabでコードも試す

[Colab版](https://colab.research.google.com/github/shogo-ishikawa/2026_3Q_M3Th3/blob/main/projects/password-lab/password_lab.ipynb)を開き、セル1から5まで順に実行します。リンクからそのまま作業でき、編集内容を残す場合は「ドライブにコピーを保存」を選びます。

| セル | 操作 |
| --- | --- |
| 1：準備 | 必要なライブラリを準備します。GPUを使う場合はColabの「ランタイム → ランタイムのタイプを変更」でGPUを選び、`gpu_enabled`を有効にします。CPUだけでも続けられます。 |
| 2：文字列 | `source_mode`でデモ・自動生成・自分で入力を選びます。手入力は実行後の入力欄を使います。 |
| 3：探索と速度 | 各方法の時間・件数の上限を指定して実行します。探し方の結果と、Python・Numba・Numba並列・利用可能なGPUの速度を表示します。 |
| 4：推定と保存方式 | 総当たりの推定時間と、同じ文字列によるSHA-256・PBKDF2の照合時間を確認します。 |
| 5：保存 | 実験条件と集計結果をCSV・JSON入りのZIPで保存します。 |

数字4文字のデモは数字だけ、「単語＋数字」のデモは数字と小文字を使います。自動生成・手入力ではチェックした文字種を使います。入力に集合の外の文字がある場合、総当たりとその推定は対象外になります。

Colabでは辞書・単語の変形に加え、「形式のヒント」も試せます。`sakura?d?d?d?d`は「sakura＋数字4文字」、`?d?d?d?d`は数字4文字です。`?l`は小文字、`?u`は大文字、`?s`は記号、`??`は固定文字の`?`を表します。一部を知っている仮定なので、予想が外れれば見つかりません。

速度比較は同じ候補範囲を3回ずつ全走査し、中央値を使います。Numbaの初回変換やGPUの準備時間は別表示です。総当たりには実測で最も速かった方式を使い、辞書・単語の変形・形式のヒントはPythonの`hashlib`で照合します。小さな問題では準備や分担の負担が大きく、並列化で遅くなる場合もあります。

総当たりはバッチ単位で計算します。発見後もそのバッチを最後まで処理するため、件数には余分な照合が含まれ、時間上限を少し超える場合があります。

結果ZIPには入力文字列・照合用ハッシュ・形式のヒント・探索候補を含めません。ColabはGoogle上で動き、Notebookの入力や画面出力はZIPとは別に残る場合があります。共有前に確認してください。文字列を変える場合はセル2から実行し直します。

## 推定時間の読み方

使える文字がC種類、長さがL文字なら、総当たりの候補数NはCのL乗です。文字数と集合が既知で、各文字を均等に生成した正解を、速度r件/秒で探すと仮定します。

| 推定 | 計算 |
| --- | --- |
| 平均的に見つかるまで | (N + 1) ÷ (2 × r) 秒 |
| 全候補を調べるまで | N ÷ r 秒 |

人が作った単語や連番には、この平均を安全性の目安としてそのまま当てはめられません。辞書や規則で先に見つかる例も一緒に見てください。「要注意」は教材内で短時間に発見できたという意味です。未発見や長い推定時間は安全の証明ではありません。

速度は計算機・実装・端末の負荷・照合方式で変わります。SHA-256の実測速度をPBKDF2の探索時間へ流用することもできません。

### Web版とColab版の測定条件

| 項目 | Web版 | Colab版 |
| --- | --- | --- |
| SHA-256への入力 | 実験ごとの8文字ソルト＋候補 | 候補だけ |
| 辞書・規則の候補 | 今回の文字数・集合に合うもの | リスト全体。総当たりだけ選択した長さ・集合を使用 |
| PBKDF2の反復回数 | 1万回 | セル4で指定。初期値10万回 |
| 主な目的 | すぐ操作して、結果と長さの違いを体験 | コードを読み、探索方法と計算装置を比較 |

別の条件・実装なので、2つの時間の数字は直接比較しないでください。どちらのPBKDF2設定も実用の推奨値ではありません。

## 実際のサービスとの違い

この教材は保存済みの照合データを手元で何度でも試せる、オフラインの実験です。実サービスへのログインは行わず、試行回数の制限や多要素認証も含みません。表示は実サービスの突破時間ではありません。

元作品のCPU・GPU比較を引き継ぎ、照合を整数変換から実際のSHA-256に変更しています。単発のSHA-256は実用のパスワード保存方式ではありません。[詳しい前提と出典](model-notes.md)を参照してください。
