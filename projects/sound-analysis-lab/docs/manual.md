# 音の実験室の使い方

最初は合成音を使い、耳で聞こえる違いとグラフの変化を比べてみましょう。自分の曲を使う場合も、まず短い区間で流れを確かめると進めやすくなります。

## Web版で音の見方を知る

[Web版](https://shogo-ishikawa.github.io/2026_3Q_M3Th3/projects/sound-analysis-lab/)では、波形・周波数・倍音・音の明るさの説明を読めます。合成音の操作では倍音の量を変え、同じ基本周波数でも音色が変わることを聴き比べます。

再生は小さな音量から始めてください。曲や各パートを分析する場合は、ページのリンクからColab版へ進みます。

## Colabで音を分析する

[Colab版](https://colab.research.google.com/github/shogo-ishikawa/2026_3Q_M3Th3/blob/main/projects/sound-analysis-lab/sound_analysis_lab.ipynb)を開き、セル1から6まで順に実行します。リンクからそのまま試せます。変更したコードや設定を残したい場合は、Colabの「ファイル → ドライブにコピーを保存」を選んでください。

### 1. 実行環境を準備する

セル1を実行します。基本の分析に使うライブラリを準備します。実音源のパート分離にはDemucsと学習済みモデルも必要です。初回は取得のために待ち時間が発生します。

GPUを使いたい場合は「ランタイム → ランタイムのタイプを変更」で選んでください。GPUがない場合もCPUで進められます。音源の長さや実行環境で処理時間は変わるので、初めは短い区間を選ぶと試しやすくなります。

### 2. 音源と区間を選ぶ

| 入力 | 試す内容 |
| --- | --- |
| 合成デモ | 正弦波（tone）、倍音（harmonics）、合成バンド（band）を試す。楽曲ファイルや分離モデルは不要 |
| PCの音声ファイル | PCに保存した音源を読み込む |
| YouTube URL | URLから音声を取得する。配信側の制限で取得できない場合はファイル入力を使う |

分析する範囲は「全体」または「区間を指定」で選びます。時間は秒で指定し、終了時刻の0は音源の末尾を表します。最大20分、ファイルは250 MiBまでを扱います。同じ比較の途中では区間をそろえ、曲の場所を変えたいときはこのセルから実行し直してください。

圧縮された音源も、読み込み後には大きくなる場合があります。展開後512 MiBを超える区間は読み込む前に停止します。その場合は短い区間を選ぶか、サンプリング周波数・チャンネル数の少ない音源で試してください。

途中の無音や、特定のパートが演奏していない時間も曲の構造の一部です。パートごとに無音を切り詰めて、時間軸をずらす処理はしません。

### 3. 比べるパートを用意する

合成デモでは、作成時に用意したパートをそのまま使えます。AIで分離できた結果ではなく、内容が分かっている比較用の音です。

分離の「自動」は、合成デモでは既知のパートを使い、実音源ではDemucsによる4パート分離を行います。「分離しない」を選ぶと原曲だけを分析できます。実行装置も「自動／CPU／GPU」から選べます。

| パート | 内容 |
| --- | --- |
| ボーカル（vocals） | 歌声などとして推定された成分 |
| ドラム（drums） | 打楽器として推定された成分 |
| ベース（bass） | ベースとして推定された成分 |
| その他（other） | 上の3パート以外として推定された成分 |

「その他」は伴奏全体ではありません。ピアノ、ギター、シンセサイザーなどが含まれることがありますが、完全に楽器を分類した結果ではありません。分離後の音を実際に聴き、ほかの音が残っていないかも確かめてください。

### 4. グラフと音を比べる

原曲とパートを同じ場所で切り替えて聴きます。試聴は選択区間の先頭30秒まで、グラフとCSVは選択区間全体を扱います。曲の別の場所を聴きたい場合は、セル2でその場所からの区間を選び直してください。

| 図・指標 | まず見るところ |
| --- | --- |
| 波形 | 音の振れ幅が大きくなる時刻、音が途切れる時刻 |
| 平均スペクトル | 低い成分と高い成分のどちらが強いか、倍音がどこに並ぶか |
| スペクトログラム | どの周波数の成分が、いつ現れるか |
| スペクトル重心の時間変化 | 周波数成分の重心が、曲の中でどう変わるか |
| RMSの時間変化 | 波形の大きさの目安が、曲の中でどう変わるか |

スペクトログラムは、横軸が時間、縦軸が周波数、色が成分の強さです。横方向の線、縦方向の広がり、低い帯域への集まりを、聞こえる音と結び付けてみましょう。

スペクトル重心は音色の明るさを考える手がかりです。「重心が1000 Hzだから1000 Hzの音を歌っている」とは読めません。ドラムには高い周波数の成分もあり、歌声より重心が高くなることもあります。

無音に近い区間では重心を平均に入れません。表の有効率も確認してください。例えば、少ししか演奏していないパートの平均と、ほぼ全区間で鳴っているパートの平均は、集計した時間の割合が異なります。

### 5. 加工前後を聴き比べる

加工は任意です。「加工しない／高い音を抑える／小さい音を弱める」から選びます。対象は「元の音／ボーカル／ドラム／ベース／その他」です。まず加工前を確認し、処理を1つだけ変えて比べると違いを捉えやすくなります。

| 加工 | 何を変えるか |
| --- | --- |
| 高い音を抑える（ローパス） | 指定した周波数より高い成分を弱める |
| 小さい音を弱める（簡易ゲート） | 弱い周波数成分をしきい値に応じて減衰させる |

高い成分を弱めると、耳で聞こえる明るさや重心がどう変わるでしょうか。ゲートでは、不要に感じる音と一緒に余韻や弱い楽器音が消える場合もあります。「重心が上がった」「値が変わった」だけで、音質が改善したとは判断しません。

加工前後は同じ区間と音量基準で試聴します。パートごとに音量を最大まで引き上げる個別の正規化は行いません。

### 6. 結果を保存する

図、集計表、時間ごとの指標、分析条件をZIPで保存します。標準では音声を含めません。音声も必要な場合だけinclude_audioを有効にします。

| 保存内容 | 主なファイル |
| --- | --- |
| 分析条件 | settings.json |
| パートごとの集計 | analysis/summary.csv |
| 時間ごとの指標 | analysis/frames_*.csv |
| 4種類の図 | waveforms.png・spectra.png・spectrograms.png・features.png |
| 加工前後の結果 | processing側の表・時間ごとの指標・図 |

CSVは表計算ソフトでも開けます。追加する音声は各パートを個別に最大化せず、元の振幅を保持するWAVです。

入力したURLと元ファイル名は分析結果へ保存しません。ただし、Colabの入力欄や画面出力は結果ZIPとは別にNotebookへ残る場合があります。Notebookを共有するときは、入力と出力も確認してください。

## 音源を利用するときに

自分で録音した音や、利用条件を確認した音源で試してください。YouTubeに公開されていることと、ダウンロード・編曲・再配布が許されていることは別です。「フリー」という説明だけで判断せず、配布元の条件やクレジットの要否を確認しましょう。

分離したパートや加工後の音声を公開する場合も、元音源の利用条件を確認します。図・数値だけを保存する初期設定から、必要なものを選んで持ち帰れる構成にしています。

## うまく進まないとき

| 状態 | 確認すること |
| --- | --- |
| YouTubeから取得できない | URLと利用できる動画かを確認。取得できるMP3などがあればファイル入力へ切り替える |
| モデルの取得や分離が進まない | まずデモで基本の分析を試す。実音源は短い区間にし、ランタイムのGPU設定や表示されたエラーを確認する |
| 一部のパートが小さい・ほぼ無音 | 元の音源にそのパートがあるか試聴し、有効率も確認する |
| 重心の平均が出ない | 対象区間が無音に近い可能性がある。波形とRMSを確認し、別の区間で比べる |
| 設定変更前の結果が残っている | 音源や区間を変えた場合はセル2から順に実行し直す |

分析方法と単位を詳しく知りたい場合は[測定値の読み方](model-notes.md)、コードを変更する場合は[開発手順](development.md)を参照してください。
