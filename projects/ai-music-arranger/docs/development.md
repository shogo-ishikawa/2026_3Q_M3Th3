# 学生作品からの改良と、コードの学び方

## 受け継いだ作品の考え方

この教材は、2026年度3Q（月3木3クラス）の学生2名による「AI作曲アレンジ」をもとにしています。学生作品は、YouTubeやPCの音源からテンポ・キー・メロディを推定し、コード伴奏やドラムを重ねて、音声とMIDIへ出力するものでした。

音楽の専門知識が多くなくても、ボタンやプルダウンで設定を変えながら作曲・アレンジを試せることが、作品の狙いです。公開版でも、次の流れと主要な機能を引き継いでいます。

- YouTubeからの音源取得、手元のファイル、デモ音源という3種類の入力。
- Librosaによるテンポ・音の特徴の分析と、pYINによる音高推定。
- コード伴奏・ドラム・抽出メロディを個別に加える操作。
- 原曲に音を重ねて再生し、WAVとMIDIで保存する機能。

元のNotebookとショートトーク資料は、作品の目的や操作の意図を確認するために参照しました。学生の氏名・学籍番号、実行結果、個別の音源URLを公開用ファイルへ転記していません。

## 公開版で改良した点

| 項目 | 提出コードで確認した状態 | 公開版の方針 |
| --- | --- | --- |
| スケール | 選択欄はあるが、伴奏を作る処理では選択値を使っていなかった | スケールの音の並びからコードを作り、選択が音へ反映されるようにする |
| コードの基準音 | 音階の番号に加える基準値によって、指定したキーと実際の響きがずれる箇所があった | キー・スケール・音の高さを分けて扱う |
| メロディの末尾 | 最後の音が音源の終わりまで続くと、音符として確定されない場合があった | 最終フレームの後でも、残った音を確定する |
| 音源の変更 | 別の音源を読み込んでも、前の音源の解析結果や生成ファイルが残り得た | 音源と結果の対応を管理し、古い結果の保存を防ぐ |
| 音の長さ | 原曲と合成音のうち、短い方に合わせてミックスを切っていた | 原曲の区間長を保ち、追加音が短くても途中で切れないようにする |
| 音色の準備 | 大きなSoundFontの外部取得に依存し、失敗時の簡易音源ではドラムを鳴らしていなかった | 外部の楽器音源がなくても伴奏とドラムを鳴らせる簡易合成を用意する |
| YouTube取得 | 取得時の失敗や環境の変化に対応する余地があった | 選択区間の取得、実行環境の確認、失敗時の案内をまとめる |
| 説明と実装 | 説明にLSTMやMarkovによる自動作曲があったが、その操作セルは提出ファイルに含まれていなかった | 現在の実装でできる音声分析・伴奏生成を説明し、実装されていない機能を案内しない |

初めて使う方が迷わず動かせるように、変更の理由を記録しています。新しい機能を加える際も、元の作品の「入力して、聴いて、設定を変えて試す」という分かりやすさを保ちます。

## v1.0.1の操作方法の変更

v1.0.0では操作画面をウィジェットとして表示していました。ウィジェットが描画されないと音源の選択欄まで使えなくなるため、v1.0.1ではColab標準フォームを通常の入口にしました。

- セル3で音源・URL・区間を指定し、読み込みと解析を実行します。
- セル4で伴奏の設定を選び、生成と聴き比べを行います。
- セル5で保存形式を選び、最後に生成した結果を保存します。

全コードセルは `@title` と `cellView: form` でコードを折りたたみます。入力欄と実行結果を表示したまま、必要なときにコードを開いて読めます。コードをファイルへ保存するセルも通常のPythonとして実行できるようにし、先頭行に依存するセルマジックは使っていません。

フォームで値を変えた後はセルを実行して反映します。特にセル4の設定を変更したら、保存前にセル4を再実行します。音源を読み込み直す際は生成結果を無効にし、前の音源の結果と取り違えないようにします。

## v1.0.2の入力とデモ

標準の音源指定を「URLがあればYouTube」に変更しました。URL欄に入力があればYouTubeから取得し、空欄なら選択したデモを使います。v1.0.1ではURLを貼り付けても「デモ音源」の選択が優先されるため、入力が無視されたように見える状態でした。今回の変更で、URLを貼ってセル3を実行する操作と実際の処理を一致させます。

デモはオリジナル曲だけでなく「きらきら星」「歓喜の歌」なども選べるようにしました。使うのはパブリックドメインの旋律をプログラムで合成した音です。既存の演奏録音は収録していません。

ユーザー向けの説明は、音源の選択・生成・保存の順に短く整理しています。処理方式や開発用の情報はこのページとローカル開発手順へまとめました。

## v1.0.3の準備セル

プログラムを読み込む3セルを1つにまとめました。セル1で環境を準備し、セル2を1回実行すれば音源の選択へ進めます。内部のPythonファイルは役割ごとに分けたまま、Notebookでの操作回数を減らしています。

YouTubeの音声取得は動画の利用条件だけで決まりません。通信やサービス側の制限で取得できない場合は、公式のMP3を保存して「PCの音源」で読み込む手順を案内します。

## 処理を読む順番

コード伴奏は4拍子を基本にしています。7音のスケールでは音階の第1・第5・第6・第4音を基準に和音を並べるため、長調ではI–V–vi–IV、自然短音階ではi–v–VI–ivとなります。ペンタトニックでは、その5音の中から和音を作ります。この場合は、通常の長調と同じコード名の並びにはなりません。

| ファイル | 主な役割 | 最初に見る点 |
| --- | --- | --- |
| `audio_input.py` | URLの確認、YouTube取得、音源の区間読み込み | 取得する処理と、音声データを使う処理を分けている点 |
| `music_core.py` | デモ曲、音源の分析、コードとドラムの生成、音の合成 | スケールの辞書、音符のリスト、伴奏を繰り返す処理 |
| `notebook_session.py` | 音源の状態管理、解析・生成の呼び出し、再生、保存 | フォームの値が、どの処理へ渡されるか |
| `colab_app.py` | 従来のウィジェット版の画面 | 部品を組み合わせる別の表示方法 |
| `ai_music_arranger.ipynb` | 準備と操作の入口 | 上から実行すると、どのプログラムが読み込まれるか |

フォームをつなぐ処理をいきなり全部読む必要はありません。まず、`music_core.py`の「設定を受け取り、音符を作る」部分を読んで、入力と出力の関係を確かめましょう。

## Pythonの基礎と結び付ける

### 辞書：スケールと音色を管理する

スケールは、基準音から何半音離れた音を使うかを、数値の並びで表せます。例えばmajorは `[0, 2, 4, 5, 7, 9, 11]` です。辞書で名前と並びを対応付けると、画面の選択を実際の計算へつなげられます。

まずスケールの辞書を探し、majorとnatural_minorの違いを確認してください。違う数字が、どの音へ対応するかを調べると、音の印象とコードの関係が見えてきます。

### リスト：コード進行やリズムを表す

コード進行は、どの和音をどの順番で使うかという並びです。ドラムのリズムも、1小節を分割した位置のうち、どこで音を鳴らすかという並びで表せます。

最初はリストの要素を一つだけ変更し、同じ音源・同じ設定で生成してください。変更した位置と、実際に聴こえた音の変化が対応しているかを確認しましょう。

### for・if：音を並べる

音符を順番に作る処理では繰り返しを使い、ドラムを鳴らす位置やパートのオン・オフには条件分岐を使います。音が鳴る条件を日本語で書いてからコードを読むと、処理を追いやすくなります。

例えば、「小節の最初でバスドラムを鳴らす」「特定の位置でスネアを鳴らす」といった規則を、自分で説明してみましょう。

### 関数：分析・生成・表示を分ける

音源の取得、特徴の分析、伴奏の生成、画面の表示は、それぞれ別の役割です。関数へ分けることで、画面を変える作業と、音の計算を変える作業を区別できます。

AIへ改良を依頼する場合も、「画面の説明を変えたい」のか、「伴奏の作り方を変えたい」のかを具体的に伝えてください。変更後は、同じ音源と設定で動かし、依頼した部分が変わったかを確かめます。

## 小さく発展させる例

| 発展案 | 最初の一歩 | 確認すること |
| --- | --- | --- |
| ドラムのリズムを増やす | 既存のパターンをコピーし、鳴る位置を一つ変更 | 原曲のテンポと同じ条件で比較できるか |
| コード進行を選べるようにする | 既存の並びと、別の並びの2種類を用意 | スケールとキーの設定が引き続き反映されるか |
| 抽出メロディを見やすくする | 音符の高さと長さを表示する | 聴いた音と表示された音符が対応するか |
| アレンジの違いを記録する | 変更した項目と気付いた点を表へまとめる | 同じ区間・設定で再現できるか |

最初から機能をたくさん増やすよりも、「一つ変えたときに、なぜこの音になったか」を説明できる変更を積み重ねると、コードの理解と作品の改良を両立しやすくなります。

## 手法と外部ライブラリ

| 技術 | 使う目的 | 参照先 |
| --- | --- | --- |
| yt-dlp | YouTubeから指定区間の音源を取得 | [公式リポジトリ](https://github.com/yt-dlp/yt-dlp)、[JavaScript実行環境の準備](https://github.com/yt-dlp/yt-dlp/wiki/EJS) |
| FFmpeg | 音声形式の変換と区間の切り出し | [公式ドキュメント](https://ffmpeg.org/documentation.html) |
| Librosa | テンポ、クロマ、音の高さの分析 | [公式ドキュメント](https://librosa.org/doc/0.11.0/) |
| pYIN | 音源の中で目立つ音の高さの推定 | [LibrosaのpYIN解説](https://librosa.org/doc/0.11.0/generated/librosa.pyin.html) |
| PrettyMIDI | 音符をMIDIへ書き出す | [公式ドキュメント](https://craffel.github.io/pretty-midi/) |
| ipywidgets | 従来のウィジェット版の操作パネル | [公式ドキュメント](https://ipywidgets.readthedocs.io/) |

pYINは確率的な音高推定手法です。元になる手法は、Mauch, M. and Dixon, S. (2014), “pYIN: A fundamental frequency estimator using probabilistic threshold distributions”, ICASSPです。

キーの推定、拍の推定、メロディ抽出はいずれも自動的な推定です。正確な採譜や音源分離として扱わず、実際の音と比較して判断してください。現在の音源合成は簡易的なものなので、リアルな楽器の音色を追求する場合は、別の音源を選べる拡張として検討できます。

## 実行環境と保存形式

YouTube取得にはyt-dlpと対応するEJS、FFmpeg、Deno 2.3以降またはNode.js 22以降を使います。Colabでは準備セルが確認します。入力欄の状態と、外部サービスによる取得制限を区別して案内します。

ZIPには `mixed.wav`、`accompaniment.wav`、`arrangement.mid`、`settings.json`、`README.txt` を保存します。設定ファイルへ取得元URLやアップロード元のファイル名は記録しません。再現用の取得元は利用者自身のメモに残します。

「AI作曲アレンジ」は元の作品名を継承しています。実装は音声分析と規則に基づく伴奏生成で、大規模な生成モデルやLSTMは使っていません。
