# AI作曲アレンジ 操作マニュアル

音源を読み込み、その特徴を分析して伴奏やドラムを重ねます。最初はデモで操作を確かめ、慣れたらPCやYouTubeの音源で試してください。

## 1. Colabを開く

**[Google Colabで開く](https://colab.research.google.com/github/shogo-ishikawa/2026_3Q_M3Th3/blob/main/projects/ai-music-arranger/ai_music_arranger.ipynb)**

PCのブラウザでリンクを開き、Googleアカウントでログインします。PCへPythonを導入する必要はありません。通常のCPUランタイムで使えます。

変更を保存したい場合は「ファイル → ドライブにコピーを保存」を選びます。既に古い版をコピーしている場合は、上のリンクから最新版を開き直してください。ドライブ内の以前のコピーは自動では更新されません。

コードは折りたたみ、入力に使うColab標準フォームを表示しています。コードを見る場合は、セルのメニューから「コードを表示」を選べます。

## 2. 最初の準備

**1 → 2-a → 2-b → 2-c** の左にある ▶ を順に押します。処理中のセルが止まり、完了表示が出てから次へ進みます。

| セル | 内容 |
| --- | --- |
| 1. 環境を準備する | 音声解析ライブラリ、FFmpeg、YouTube取得用の実行環境を準備 |
| 2-a. 音源の取り込みを読み込む | 音源の取得・変換に使うプログラムを保存 |
| 2-b. 解析と伴奏生成を読み込む | 音を解析し、伴奏を作るプログラムを保存 |
| 2-c. 再生と保存を読み込む | 各フォームの操作をつなぐプログラムを保存 |

初回の準備には数分かかることがあります。YouTube用の追加準備に失敗した場合は表示を確認してください。デモとPC音源で操作を続けられます。

ランタイムを再起動した場合や接続先が新しくなった場合は、1から実行し直します。音源やアレンジ設定だけを変える場合は、該当するセル3以降を実行すれば構いません。

## 3. セル3で音源を選ぶ

セル3のフォームで種類を選び、**セル3の ▶** を押します。音源の読み込みとテンポ・キーの解析が続けて行われます。

| 入力欄 | 意味 | 初期値 |
| --- | --- | --- |
| `input_source` | 「デモ音源」「YouTube」「PCの音源」から選ぶ | デモ音源 |
| `youtube_url` | YouTubeを選んだときに使う動画URL | 空欄 |
| `start_seconds` | 動画・ファイルの何秒目から使うか | 0秒 |
| `duration_seconds` | 何秒分を読み込むか。3〜60秒 | 20秒 |

### デモ音源で試す

`input_source` は「デモ音源」のまま実行します。プログラムが12秒のメロディを合成するので、URLやファイルを用意する必要はありません。デモでは開始位置と長さの指定は使いません。

### YouTubeを使う

1. `input_source` を「YouTube」にします。
2. `youtube_url` に、取得・編集する許可がある動画のURLを貼り付けます。
3. 開始位置と長さを入力します。
4. セル3の ▶ を押し、原曲の再生欄が出るまで待ちます。

例えば `start_seconds` が30、`duration_seconds` が20なら、30秒目から50秒目までを使います。音源の終わりに達した場合は、指定より短くなることがあります。

YouTubeで動画を再生しただけではNotebookへ音源は読み込まれません。セル3を実行して取得します。公開状態やネットワーク、YouTube側の制限によって取得できない動画もあります。

### PCの音声ファイルを使う

`input_source` を「PCの音源」にし、開始位置と長さを指定してセル3を実行します。表示されたファイル選択からWAVやMP3などの音声ファイルを1つ選んでください。アップロードできる大きさは50 MiBまでです。

### 読み込み後に確認する

原曲の再生欄と、推定BPM・キーが表示されます。再生して使いたい区間になっているか確認します。

BPMは1分間の拍数です。120 BPMなら1拍は0.5秒になります。キーは曲の中心に感じられる音の候補で、Cはド、Dはレ、Aはラに対応します。どちらも推定値なので、原曲を聴きながら後で修正できます。

フォームの値を変えただけでは音源は変わりません。別の種類や区間を使う場合はセル3を再実行します。取り込みに失敗した際は前の音源を保持しますが、古い生成結果は保存対象から外します。

## 4. セル4でアレンジを生成する

最初は初期設定のまま **セル4の ▶** を押してください。原曲・追加パート・ミックスの再生欄が表示されます。

フォームの値を変更した後も、セル4を実行して音を作り直します。実行前の入力変更は音声へ反映されません。

### 自動設定と手動設定

| 入力欄 | オンのとき | 手動で変える方法 |
| --- | --- | --- |
| `auto_tempo` | 推定BPMを使用 | オフにして `bpm` にテンポを指定 |
| `auto_key_scale` | 推定キーとスケールを使用 | オフにして `root` と `scale` を選択 |
| `auto_beat` | 推定した拍の位置から伴奏を開始 | オフにして `beat_offset` に秒数を指定 |

例えば長調と短調を比べたい場合は `auto_key_scale` をオフにします。`root` をCに固定し、`scale` をmajorからnatural_minorへ変えて生成してください。自動設定がオンのままでは、手動欄を変更しても推定値が使われます。

`beat_offset` は切り出した音源の中で伴奏を始める位置です。動画の30秒目から使い、その区間の0.3秒目に最初の拍がある場合、セル3の開始位置は30、セル4の `beat_offset` は0.3です。

**BPMは追加する伴奏・ドラムの速さを変えます。原曲の速さは変わりません。** 原曲と合わせる場合は、原曲に近いBPMを指定してください。推定BPMが半分や2倍になる場合もあります。

### キー・スケール・音色

| 入力欄 | 内容 |
| --- | --- |
| `root` | コード伴奏の基準となる音。C、C#、Dなど |
| `scale` | 伴奏に使う音の並び |
| `instrument` | コード伴奏の音色 |

| `scale` の選択肢 | 音の並び |
| --- | --- |
| major | 長調 |
| natural_minor | 自然短音階 |
| harmonic_minor | 和声的短音階 |
| dorian | ドリアン |
| mixolydian | ミクソリディアン |
| pentatonic | 長調の五音音階 |

| `instrument` の選択肢 | 音色の目安 |
| --- | --- |
| Electric Piano | エレクトリックピアノ |
| Acoustic Grand Piano | グランドピアノ |
| Acoustic Guitar | アコースティックギター |
| Electric Guitar | エレクトリックギター |
| Strings | 弦楽器の合奏 |
| Synth Lead | シンセサイザーの旋律向けの音 |
| Music Box | オルゴール |

音色は内蔵の簡易音源です。大きな楽器音源を追加取得せずに試せます。原曲のコード進行を採譜する処理ではないため、キーと拍を合わせても原曲と同じ和音になるとは限りません。

### 加えるパートと音量

| 入力欄 | 内容 |
| --- | --- |
| `add_chords` | コード伴奏を加える |
| `add_drums` | ドラムを加える |
| `add_melody` | 原曲から推定した音高を音符として加える |
| `original_gain` | 原曲の音量 |
| `chord_gain` | コード伴奏の音量 |
| `drum_gain` | ドラムの音量 |
| `melody_gain` | 抽出メロディの音量 |
| `humanise` | 0〜1で指定するタイミングと強弱の揺らぎ |
| `seed` | 揺らぎを作る乱数の初期値。同じ値で比較できる |

音量は0〜1.5で指定します。0にしたパートは聴こえなくなります。最初は `add_melody` をオフにして伴奏とドラムを聴き、その後に抽出メロディを加える方法も試してみてください。

抽出メロディは声だけを分離した音声ではありません。pYINで音の高さを推定し、音符として鳴らします。複数の声や楽器が重なる区間では、狙った旋律と異なる音を拾うことがあります。

### 聴き比べる

生成後は次の3つを再生できます。

1. **原曲**：読み込んだ区間。
2. **追加パート**：コード伴奏・ドラム・抽出メロディをまとめた音。
3. **ミックス**：原曲と追加パートを重ねた音。

音符の図は横軸が時間、縦軸が音の高さです。抽出メロディとコード伴奏の線を見ながら、聴こえた音と比べてください。ドラムは図には表示しません。

## 5. セル5で保存する

セル5の `save_format` で形式を選び、▶ を押します。セル5は最後に生成した結果を保存します。セル4の設定を変えた場合は、セル4を再実行してから保存してください。

| 選択肢 | ファイル | 用途 |
| --- | --- | --- |
| ZIP一式 | `arrangement_results.zip` | 音声・音符・設定をまとめて保存 |
| ミックスWAV | `mixed.wav` | 原曲と追加パートを重ねた音を保存 |
| MIDI | `arrangement.mid` | 追加パートの音符を対応ソフトで編集 |
| 追加パートWAV | `accompaniment.wav` | 追加パートだけを保存 |

ZIPには `mixed.wav`、`accompaniment.wav`、`arrangement.mid`、`settings.json`、`README.txt` が入ります。

MIDIには原曲の録音は含まれません。音の高さ・長さ・強さなどが記録され、再生ソフトによって音色が変わります。響きも含めて残す場合はWAVを選びます。

設定ファイルにはアレンジの値と区間の情報を記録します。YouTube URLやアップロード元のファイル名は記録しません。再現に必要な取得元は自分用のメモへ残してください。ミックスの公開・共有では、入力音源の利用条件も確認してください。

Colabの作業用ファイルはセッション終了時に消えることがあります。残したい結果はPCへ保存します。

## 困ったとき

| 状況 | 確認・対処 |
| --- | --- |
| セル3に音源やURLの入力欄がない | 上のリンクから最新版を開き直します。v1.0.1はセル3の標準フォームに `input_source` と `youtube_url` を表示します |
| セル3に従来の操作パネルしかない | ドライブに保存した古いコピーの可能性があります。最新版を開いて新しくコピーします |
| コードを読みたい | セルのメニューから「コードを表示」を選びます |
| 接続が切れた／変数がない | ランタイムが新しくなった可能性があります。1から順に実行します |
| YouTubeから取得できない | URLと公開状態を確認し、セル1を再実行して取得ツールを更新します。別の動画やPC音源でも試します |
| FFmpegやJavaScript実行環境がない | セル1を実行し直し、その案内を確認します |
| 開始位置を変えても同じ音が出る | セル3を再実行して新しい区間を読み込みます |
| 設定を変えても音が変わらない | 自動設定のチェックを確認し、セル4を再実行します |
| 音が出ない | 再生ボタン、PCのミュート、各パートの音量を確認します。デモでも試します |
| 区間に音源がない | `start_seconds` を0に戻してセル3を実行します |
| 処理に時間がかかる | まず10〜20秒で試します。セル4の `add_melody` をオフにすると音高抽出を省けます |
| テンポが合わない | 推定BPMの半分・2倍を検討し、`beat_offset` も調整します |
| 和音が合わない | 手動でキーとスケールを変えて比較します。原曲のコードを推定する機能ではありません |
| メロディが変／音符が出ない | 単音がはっきり聴こえる区間を選びます |
| 保存結果が古い | セル4で新しい設定を生成してからセル5を実行します |

YouTube取得にはyt-dlpと対応する補助パッケージを使います。Deno 2.3以降またはNode.js 22以降を、準備セルで確認します。独自に環境を変更する場合は[yt-dlp公式の案内](https://github.com/yt-dlp/yt-dlp/wiki/EJS)も参照してください。

## 授業・グループワークで試す

同じ音源・同じ区間を使い、設定を一つだけ変えます。変更後は毎回セル4を実行します。

| 実験 | 記録すること |
| --- | --- |
| `add_drums` のオン・オフ | 拍が分かりやすくなったか、原曲とずれていないか |
| majorとnatural_minorの比較 | どの音や和音が変化したか、印象がどう変わったか |
| `original_gain` を0にする | 何が生成されているか |
| `humanise` を変える | タイミングや強弱の違いが聴き取れるか |
| 音源の区間を変える | 単音と多重奏で抽出結果がどう変わるか |

どの設定がどの音へ影響したかを説明できると、次に改良したいコードも見つけやすくなります。
