# 公開版の確認記録

確認日：2026年11月10日（日本時間）。対象：v1.0.0。

## 動作を確認したこと

`python -m pytest -q tests` で、60件すべてが合格しました。

| 対象 | 確認内容 |
| --- | --- |
| 音声入力 | 実際のFFmpegで指定区間の切り出し、モノラル化、22050 Hzへの変換、曲末の短い区間、不正なファイルを確認 |
| 音高推定 | 実際のpYINで440 Hzの単音を推定。音源の最後まで続く音も音符に残ることを確認 |
| 音楽処理 | 長調と短調の構成音、音量0、ドラム、音源全体の長さ、無音・短い音源、乱数の再現性を確認 |
| 出力 | WAVのサンプル数、MIDIのテンポ、ZIPのファイル構成と設定内容を読み直して確認 |
| 状態管理 | 設定変更後に古い結果を保存できないこと、取り込み失敗時に前の音源を保持すること、メロディ解析の再利用を確認 |
| 準備処理 | 再実行しても作業フォルダーが入れ子にならないこと、yt-dlpと補助パッケージが更新対象になることを確認 |
| YouTube取得処理 | URL検査、区間指定、再生リストを取得しない設定、失敗時の既存音源保持、タイムアウト時の子プロセス停止を確認 |
| 配布Notebook | nbformatで形式を検証。5つのコードセルの内容がPythonファイルと一致し、出力・実行番号・ウィジェット状態が残っていないことを確認 |

別途、実際の12秒デモで「解析 → pYINで音高を抽出 → 生成 → WAV・MIDI・ZIP保存」を実行しました。配布Notebookだけを新しい作業フォルダーへ持ち込み、IPythonで準備を含む5つのコードセルを順番に実行した場合も、同じ流れが完了しました。設定を変えて再生成した際に、音が変化し、メロディ抽出を使い回せることも確認しています。

実装とは別の担当によるコードレビューと操作コールバックの確認も実施しました。レビューで見つけたゆらぎの単位表示、準備の再実行、ローカル保存リンク、取得ツールの更新方法は修正済みです。

確認環境はLinux、Python 3.12.14、Librosa 0.11.0、NumPy 2.5.4、SoundFile 0.13.1、PrettyMIDI 0.2.11.post0、ipywidgets 8.1.9、FFmpeg 7.1.5です。YouTube取得処理はyt-dlp 2026.10.26、yt-dlp-ejs 0.8.0、Node.js 24.22.1で確認しました。

## YouTubeの実通信で確認できた範囲

公開されているテスト用動画を使い、動画情報の取得とJavaScriptによる処理は成功しました。一方で、この検証環境では音声配信先が音声の代わりに「Site Unavailable」というHTMLを返すため、指定区間をWAVへ保存するところまでは確認できませんでした。通常のOpus形式でも同じでした。

この結果から、YouTube取得が実環境でも成功したとは判断していません。取得機能を残した状態で、実際に利用するColabの接続先と動画で確認する必要があります。取得に失敗した際はエラーを表示し、前の音源を保持します。勝手にデモへ切り替えません。

## 実環境で未確認のこと

- Google Colabのブラウザ画面での操作と、その環境からのYouTube音声取得。
- ブラウザでの最終的な配置・描画。検証環境ではChromiumがソケット作成時の `Operation not permitted` で起動できず、Jupyterカーネルも同じ実行制限で起動できませんでした。音の処理、ウィジェットの状態変更、NotebookのコードはPython・IPythonから確認しています。
- 対応するJavaScript実行環境がないColabにおける、Denoの自動導入。今回の環境には対応するNode.jsが存在したため、自動導入経路は実行していません。配布コードは公式の固定バージョンとチェックサムを使います。
