# 同じ食事内の二重計上の確認

対応版：v3.14.0

`mealOverlapWarnings(incomingEntry, existingEntries, data, {excludeEntryId, focusItemIds})` は、これから登録する食事と、同じ日付・朝昼夕などの食事区分・予定か実績かが一致する記録だけを比較します。新しく一括登録する料理同士も比較します。返り値は警告の一覧で、入力の記録や材料・栄養を変更しません。

## 確認する組み合わせ

- ご飯を含むカレー・丼・定食などと単品のご飯。玄米や麦ご飯も対象です。
- 同じ料理名・基準量・材料・栄養・外食の表示範囲が一致する料理の重複。食べた量が異なる場合も追加分として確認します。

ご飯の包含は、登録時点の材料へ明示された米飯か、外食の `riceIncluded` を使います。原材料が未確認の場合は、登録元のレシピにも同じご飯が明示され、記録時点の材料にも残っている場合だけ使います。名前やメモに「ご飯」と書かれているだけでは判定しません。米粉は米飯として扱いません。

ルーのみのカレー、主菜とご飯、ご飯を含まない麺とご飯へ一律に注意を出しません。完全に栄養・材料が未入力で登録元もない料理は、同じ名前だけで同一の料理と断定しません。

## 追加・おかわりとして登録できる

確認は案内です。追加のご飯やおかわりを食べた場合は、確認後にそのまま登録できます。自動で料理を消したり量を減らしたりしません。編集時は `excludeEntryId` で編集前の記録を比較から外します。予定と実績は別の状態として比較します。

既存の食事へ料理を追加し、更新後の食事全体を渡す場合は、`focusItemIds` に新しく追加した料理IDの配列を指定します。指定した料理を含む組み合わせだけを、重複排除や20件の上限より先に選びます。以前に確認して登録済みの2皿があっても、3皿目の追加確認を省略しません。`null` または未指定なら全料理、空配列なら確認対象なしです。

警告は同じ内容をまとめ、画面で確認できるよう最大20件を返します。`code`、`message`、`actionLabel`、対象の料理・記録ID、料理名を持ちます。`rice-included` の推奨確認文言は「追加のご飯として登録」、`duplicate-dish` は「追加分として登録」です。

この判定は入力済みの内容の確認を助けるためのもので、食べた事実を判定する機能ではありません。
