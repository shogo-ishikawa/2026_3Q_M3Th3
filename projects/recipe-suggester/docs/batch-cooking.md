# 作り置きと取り分け

完成した料理の容器を除いた重量と、元レシピの何人分を作ったかを登録します。元レシピの材料と栄養を調理時点で保存し、食べるたびに完成重量のg数を入力します。

例：4人分を作り、完成重量が1200gになった料理を150g食べる場合、料理全体の1/8の栄養を記録します。材料は調理前の状態ですが、取り分けの比率には実測した完成重量を使うため、水分の蒸発後も分けられます。料理全体に材料が均等に含まれるという概算です。煮汁や油だけを残した場合や、具材を選んで取った場合の差は自動で補正しません。

予定に入れた量も取り分け予約として残量から引きます。予定を実績に切り替えても、同じ取り分けを重ねて引きません。記録を削除したり取り分け量を減らしたりすると、その分が残量へ戻ります。完成重量を超える登録はできません。

登録中の作り置きを「終了」すると新たな取り分けを止めます。調理時のデータと過去の食事は残します。過去の記録が参照する作り置きを削除することはできません。

調理済みの取り分けは買い物リストに加えません。調理前に材料を買う場合は、通常の献立予定から材料をまとめてください。作り置きの詳細にも調理時の材料を表示します。

## 保存形式

`batches`は最大200件。各項目は`id`、`name`、`preparedDate`、`totalGrams`、`sourceQuantity`、`item`、`archived`です。`item`には全体の材料と栄養を`quantity: 1`、`portion: {amount: totalGrams, unit: 'g'}`として保存します。

食事内の取り分け項目は`batchId`を持ち、完成品100g当たりの材料と栄養を保存します。`quantity`は食べるg数÷100です。残量は予定と実績の項目から毎回求め、別の消費済みカウンターは保存しません。栄養が不明な項目は不明のまま重量比で引き継ぎます。

`validateBatches(raw, data, {validateItem})`には既存の食事項目を検証する処理を渡します。その後、`assertBatchUsage(batches, entries)`が参照、調理日以降の取り分け、100gの基準量、残量を検証します。取り分けの栄養・材料・食材やアレルギーの情報・店舗情報も、調理時に保存した全体のスナップショットと一致することを確認します。現在の食材DBから再計算せず、浮動小数点の微小な丸め差だけを認めます。
