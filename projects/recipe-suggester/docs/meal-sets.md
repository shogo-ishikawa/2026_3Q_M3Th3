# 定番セットと過去の食事のコピー

「記録」タブの「定番セット・過去の食事を使う」から、よく食べる組み合わせをまとめて登録できます。

- 過去の食事は日付・朝昼夕／間食・食べた／予定を選びます。同じ枠に複数回登録した料理もまとめて表示します。
- そのまま別の日へコピーするか、名前を付けて定番セットに保存します。セットは100件まで、1セットは100品までです。
- 登録先の日付・食事・予定／実績・量の倍率を指定します。現在の記録へ追加し、既存の記録は置き換えません。
- セットには保存元の料理と量を保存します。量の倍率はカレンダーへ登録するときにだけ掛けます。異なる料理や量は登録後に編集できます。
- 名称・材料・栄養・基準量は保存時点の情報を保持します。後のレシピDB更新でも変わりません。栄養が不明な項目は不明のままです。
- 除外中の食材・アレルゲンや原材料が未確認の料理は、画面に注意を表示します。食べた事実や予定の手動記録は可能ですが、自動献立への推薦とは別です。
- 作り置きを取り分けた記録はコピー・セット保存できません。残量の二重使用を防ぐため、作り置きの残量画面から登録してください。
- 定番セットは記録のJSON書き出し・読み込みに含まれます。セットを削除しても、カレンダーへ登録済みの食事は残ります。

## 実装の入口

`meal-sets.js`は`createMealSet`・`createRepeatedMeal`・`validateMealSets`・`mealSetWarnings`を提供します。コピーでは新しいentry/item IDを発行し、栄養の基準値や材料は再計算せず`quantity`にだけ倍率を掛けます。

`mountMealSets({state,data,date,meal,status,onSave,onDelete,onAdd,onError})`が操作画面を返します。保存は呼出元の`commit`で行い、更新後に画面を再描画します。永続化する追加項目は`mealSets: [{id,name,note,items}]`です。保存データの検証にはjournalと共通の`validateFrozenItems`を使います。
