# メニューの中で種類を選ぶ

対応版：v3.7.0 ／ 更新日：2026年11月13日

同じ料理の具や味の違いは、一覧へ一品ずつ並べる代わりに、メニューを開いてから選べるようにします。選んだ種類の材料、栄養、作り方、基準量を表示し、その内容で記録します。主食のg数や寿司の貫数など、元の単位も引き継ぎます。

肉じゃがとお好み焼きは、材料を選んで配合を作る入口です。肉や具材によって材料と作り方を変える仕組みは[料理のカスタマイズ](dish-customisation.md)を参照してください。以下の料理は、確認済みの既存レシピを種類としてまとめています。

## まとめる範囲

料理の種類だけでなく、食事での役割と調理・提供形態がそろうものを対象にしました。

- 手作りのカレーとレトルトは別の入口です。購入品を手作りへ変更したり、原材料未確認の購入品を確認済みにしたりしません。
- カップラーメンと袋入り即席ラーメンは別の入口です。調理や購入単位、製品の量を区別します。
- ご飯とおにぎりは別の入口です。ご飯のgとおにぎりの個数を混ぜません。
- にぎり、細巻き、太巻き、軍艦は分けます。盛り合わせ、いなり寿司、ちらし寿司は単品として残します。
- ご飯とおかゆ、ドリアやリゾットなどの一品料理も分けます。別の主菜を組み合わせる食事と、主食を含む一品の食事を同じものとして扱いません。
- 旧来の主菜扱いの具だくさん麺と、新しい主食区分の麺は混ぜません。今ある役割を変更せず、対象となる主食区分だけをまとめます。
- 新しい料理やマイメニューは、名前が似ているだけで自動的にグループへ入れません。別の料理や独自の配合を見失わないためです。

同じ種類に似た名前のレシピがある場合も、材料や量が違う元の内訳は保っています。今回の表示整理は、栄養の数値を平均する処理や、似た料理を削除する処理ではありません。

## 検索と除外条件

先にアレルギー、除外食材、区分、食材カテゴリ、調理法、ジャンル、提供形態、検索語で候補を絞ります。その候補だけを同じメニューへまとめるため、除外した料理を表示の集約で戻しません。

例えば「カルボナーラ」を検索すると「パスタ」の入口を表示し、検索に合ったカルボナーラを選んだ状態で開けます。材料の除外によってカルボナーラが候補から外れている場合、別のパスタを開いた後でもカルボナーラを候補へ戻さないよう、詳細の選択肢にも同じ除外条件を適用します。

表示用の検索データにはグループの見出しも加えます。「カップうどん」のように具材の名前が間に入らない語でも、そのメニューへ到達できるようにするためです。元の料理名や保存データには書き戻しません。

表示件数は一覧のメニュー数と料理の内訳数を区別します。DBに855種類の内訳があっても、同じ料理をまとめた一覧は751メニューです。マイメニューを保存すると、その分のメニューが増えます。

## 記録と買い物

選んだ内訳の元のレシピIDを使います。材料の量や栄養、アレルゲン、作り方、単位を一緒に記録するため、後から一覧のまとめ方を変えても当時の内容を読めます。以前保存した「鮭おにぎり」という名前を、表示用の「おにぎり」へ書き換えることもありません。

記録の量は選んだ料理の基準量から換算します。鮭おにぎり2個を3人分の買い物へ反映するなら、その料理の材料を6個分へ換算します。ご飯や寿司も、それぞれのg・貫・切れの基準量に合わせます。

## 実装と拡張

`menu-variations.js` の `MENU_VARIATION_GROUPS` に対象のID、表示名、役割、提供形態、主食を含むかどうかを定義しています。元のレシピを変更せず、表示のためのオブジェクトだけを作ります。

| 関数 | 役割 |
| --- | --- |
| `groupMenuRecipes(candidates, {query})` | 絞り込んだ候補をまとめる。検索中は同じメニュー内の料理名一致を代表として優先する |
| `getVariationGroup(recipeId, recipes)` | 渡した一覧に残る同じ種類の選択肢と、開いたレシピのIDを返す |
| `variationSearchAliases(recipe)` | 表示用の検索データへグループの見出し名を加えるための配列を返す |
| `variantLabel(recipe)` | 元の小分類名があれば使い、なければ元の料理名を使う |
| `validateVariationDefinitions(definitions)` | 重複したグループ名や、同じ料理IDの二重所属を拒否する |

`groupMenuRecipes` に全レシピの配列を別途渡しても、非表示の候補を補って戻すことはありません。詳細へ渡す一覧も、呼び出し元で除外・区分・形態などの条件を適用します。画面の検索語だけを外して他の種類を選べるようにする場合も、アレルギーや食材除外はそのまま保持します。

今回の集約対象は855品のDBを調べて選びました。レシピや栄養の新たな出典を導入する処理ではなく、既存レシピに記録された出典を引き継ぎます。材料選択で新しく用意する配合は、別の[料理のカスタマイズ](dish-customisation.md)に出典と前提をまとめています。
