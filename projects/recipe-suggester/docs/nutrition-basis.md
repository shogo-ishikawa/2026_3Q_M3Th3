# 栄養値の根拠を一覧で確認する

対応版：v3.14.0

料理や記録に短いラベルを添え、栄養値をどのように求めたかを表示します。ラベルは精度・健康・アレルギーの安全性の採点ではありません。

| 保存する分類 | 表示 | 意味 |
| --- | --- | --- |
| ingredients | 材料から概算 | 登録した材料の代表値と使用量による概算 |
| official | 公式表示値（参考） | 参照商品・店舗、または利用者が登録した公式資料の表示値を基準にする |
| manual | 手入力 | 利用者が入力した栄養値 |
| estimate | 配合・摂取量の概算 | 参考配合や食べた割合などの仮定を使う |
| mixed | 表示値＋概算 | 表示値と別の材料・参考値を合算する |
| unknown | 根拠未記録 | 記録時に分類を保存していない |

元の詳しい出典、参照商品の規格、確認日、食材の状態は料理詳細で確認します。同じ料理名でも店舗・商品・量は異なるため、「公式表示値（参考）」は実物と一致する保証ではありません。利用者が登録した店舗メニューは、登録した資料をアプリが自動照合したものではありません。

任意項目の空欄や未掲載の成分は不明のままです。ラベルの説明にも未入力の成分を示し、0へ補いません。

## 保存と分類の扱い

`nutritionBasis` は6種類の文字列だけを保存します。新しい食事は記録時に分類を固定します。過去の食事に分類がない場合は「根拠未記録」とし、現在のDBやURLから勝手に公式表示値へ変更しません。コピー・お気に入り・作り置きへ引き継ぐ場合も、保存された根拠を保ちます。

組み込みの公式表示例は、実際の出典モジュールにあるID、基準量、材料、人数、栄養値が一致するものだけを使います。IDの接頭辞、URLの存在、説明中の「公式」という単語だけでは公式表示値と判断しません。牛乳割りのプロテインなど、表示値に別の材料の概算を加えた料理は「表示値＋概算」です。

食品成分表の材料を合算する手作り料理、参考配合の市販品、利用者の入力は別々の分類で扱います。材料の量と栄養値が対応する自作料理は材料による概算として表示できますが、根拠が判別できない自作の合計値は「根拠未記録」とします。

選択式の焼き鳥や天ぷらなども、選んだ各料理の分類を合算前に引き継ぎます。材料からの概算だけなら「材料から概算」、表示値と材料の組み合わせなら「表示値＋概算」です。表示値だけの組み合わせは、すべての参照元の説明を保存できる場合に限り「公式表示値（参考）」とします。説明が保存上限を超える場合は「表示値＋概算」にとどめます。根拠未記録の料理を含む場合は、その組み合わせも「根拠未記録」のままです。材料の量と栄養値の合計は、この分類によって変更しません。
