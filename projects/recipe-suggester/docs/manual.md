# Meal Paletteの使い方

対応版：v3.7.1 ／ 更新日：2026年11月13日

[ブラウザー版](https://shogo-ishikawa.github.io/2026_3Q_M3Th3/projects/recipe-suggester/)を開くとすぐに使えます。ログインやAPIキーは不要です。画面は「献立」「記録」「栄養」「メニュー」「買い物」「設定」の順に並び、起動時は献立を開きます。旧名は「献立ノート」です。v3.7.1は855品のレシピと372種類の食材・調味料を収録しています。肉じゃがやお好み焼きは料理の中で具材を選べます。同じ料理の種類も詳細にまとめ、ご飯のお供の単品追加やサラダの材料選択も使えます。朝・昼・夕のまとめ提案、食事ごとの主食調整、範囲リセット、メニュー詳細からの記録も使えます。

## 食事をカレンダーに記録する

「記録」で日付を選び、朝食・昼食・夕食・間食を指定します。月間カレンダーのほか、日付欄と「今日」からも移動できます。

まず「区分」で主菜・副菜・主食・汁物・飲み物・間食を選びます。初期表示は主菜です。主菜と副菜では「食材カテゴリ」から「調理法」へ絞り込み、最後に「メニュー」を選びます。主食・汁物・飲み物・間食は「種類」からメニューへ進み、複数のバリエーションがある料理はその中で具体的な種類を選びます。量を入力して追加すると同じ日・食事に複数品を登録できます。ご飯、主菜、飲み物を別々に記録して構いません。

| 選び方の例 | 記録の仕方 |
| --- | --- |
| 主食 → ご飯 → 白米・玄米・炊き込みご飯・わかめご飯 | 食べた完成量をgで入力 |
| 主食 → おにぎり → 塩・鮭・梅・ツナマヨなど | 個数で入力。ご飯とは別の種類 |
| 主食 → うどん・そば → かけ・きつね・たぬき・肉など | 画面に表示される基準量に合わせて入力 |
| 主食 → パスタ → ペペロンチーノ・カルボナーラなど | 具体的な料理を選んで量を入力 |
| 主菜 → 肉 → 揚げ物 | 唐揚げ、フライ、カツ、コロッケなどから選ぶ |
| 主食 → お寿司 → 握り・軍艦・巻物・盛り合わせ | 握り・軍艦は貫、巻物は切れ、盛り合わせは皿で入力 |
| 主菜 → 魚介 → 刺身 | まぐろ赤身・サーモン・ぶり・たいなどを選ぶ |
| 副菜 → 食材カテゴリ → 調理法 | 枝豆・冷奴・ひじき煮・サラダ・煮物などを選び、表示単位に合わせて入力 |
| 飲み物 → 水・炭酸水 → 水・レモン水・炭酸水 | 飲んだ量をmlで入力 |
| 汁物 → みそ汁 → 豆腐やわかめ、なめこなど | 具の組み合わせを選んで量を入力 |
| 間食 → チョコレート・グミ・ドーナツ・ケーキ・チーズ・ホットスナックなど | メニューの基準に合わせて本・個・袋・gなどで入力 |

食材カテゴリと調理法は、候補を絞るための選択肢です。複数の食材を使う料理は別のカテゴリから探せることもありますが、一覧には同じメニューを重複して表示しません。調理法の「揚げ物」「焼き物」「刺身」などと、「手作り」「レトルト」などの調理・提供形態は別の条件です。

料理によってg・ml・個・皿・杯などの単位が異なります。基準量の説明も表示されるので、入力欄の単位を確かめてください。例えばご飯の基準が150gなら、100gは標準の`100 ÷ 150`倍として計算します。おにぎりの大きさは収録例の目安です。商品の表示が分かる場合は手入力で補えます。

寿司は握りと軍艦を1貫、細巻・太巻は切り分けた1切れ、盛り合わせは1皿を基準にします。握りを3貫食べた場合は「3貫」、細巻を2切れなら「2切れ」と入力します。巻物1本を食べた場合は、そのメニューの説明にある切れ数へ合わせてください。過去に保存した寿司の量や栄養は記録時点の内容を保ちます。

| 記録の種類 | 栄養と買い物への反映 |
| --- | --- |
| 食べた | 自分の摂取量へ含める。買い物には含めない |
| これからの予定 | 摂取量には含めない。買い物の対象になる |

予定を食べたら「食べたにする」を押し、実際の量や内容に直します。料理名を押すと記録した栄養・材料・作り方を開けます。「編集」では日付や食事区分なども変更できます。

### ご飯のお供を単品で記録する

納豆、おろし納豆、ゆで卵は「副菜」から探します。生卵と温泉卵も単品で選べるので、卵かけご飯に固定せず、ご飯や牛丼などと組み合わせて記録できます。収録しているすき焼きは卵も含むため、その分を単品で重ねて登録しないでください。

ツナの油漬けと水煮、味付けのり、たらこ、明太子、鮭フレークも追加できます。単品にはご飯や別添えの調味料を含めません。食べた卵の個数や食品のg数を入力し、ご飯は別に記録します。別添えのたれやしょうゆを使った場合は、手入力で補えます。

ツナの液汁を含めるかなど、計量する状態は詳細の説明に合わせてください。市販品は商品や味によって栄養・原材料が変わります。参照商品の情報は[ご飯のお供の出典](accompaniment-sources.md)から確認できます。未確認の商品例は記録用で、自動提案の対象にはしません。

### サラダの材料とドレッシングを選ぶ

1. 「メニュー」で「生野菜サラダ（ドレッシングなし）」を開きます。「記録」で同じメニューを選び、「材料を選んで記録」から進むこともできます。
2. 材料を選び、それぞれの量をgで入力します。レタスやキャベツ、トマトなどは生の可食部、ブロッコリーはゆでて水気を切った状態です。
3. ドレッシングの種類と量を選びます。ドレッシングなしも選べます。
4. 組み合わせの栄養と登録アレルゲンを確認し、日付、食事区分、予定か食べた記録か、食べる量を指定して追加します。

材料のg数はサラダ1皿分です。半分を食べた場合は記録する量を0.5皿にします。材料を半分にして0.5皿と入力すると二重に半量になるため、どちらかで調整してください。買い物では記録した材料と分量に買い物用の人数を掛けます。

同じ組み合わせを繰り返し使う場合は、追加するときに「この組み合わせをマイメニューにも保存」を選べます。保存しなくても、カレンダーにはそのときの材料と栄養が残ります。後から別の組み合わせを作っても、過去のサラダは変わりません。

ドレッシングは家庭で作る配合を基準にした概算です。市販品を使って表示値に合わせたい場合は、手入力メニューとして登録できます。既存のドレッシング付きサラダを選ぶ方法も引き続き使えます。詳しい計量方法は[サラダの組み合わせ](salad-builder.md)をご覧ください。

### 肉じゃがやお好み焼きの具材を選ぶ

1. 「メニュー」で肉じゃがかお好み焼きを開きます。「記録」で選んだ料理から進むこともできます。
2. 肉じゃがは「肉の種類」で牛肉か豚肉を選びます。お好み焼きは「お好み焼きの種類」で豚玉、イカ玉、シーフード玉、もちねぎ玉、モダン焼き、ミックス玉などから選びます。「自由に調整」も使えます。
3. 「具材とトッピング」で豚ばら肉、イカ、えび、餅、ねぎ、焼きそば麺を選び、それぞれの量をgで入力します。「ソース・たれ」はしょうゆと酢、ウスターソース、ソースなしから選び、ソースとマヨネーズの量も実際に使う量に合わせます。
4. 更新された栄養と登録アレルゲン、「材料と分量」「この内容での作り方」を確認します。日付と食事区分、予定か食べた記録か、何皿分かを指定して追加します。

表示する材料は1皿分です。肉や海鮮、切り餅は加熱前の可食部、麺は蒸し中華麺の調理前重量として量ります。例えば0.5皿を登録すると、材料と栄養も半分として記録します。好みの配合を繰り返し使いたい場合は「この組み合わせをマイメニューにも保存」を選びます。保存を選ばなくても、その時の配合と栄養は食事の記録に残ります。

肉や海鮮、麺の有無に合わせて作り方も変わります。具材を変えた後は新しい手順を確認してください。ウスターソースは専用のお好み焼きソースの栄養値ではありません。実際の商品に合わせたい場合は、表示を確認してマイメニューを編集できます。配合と計量の考え方は[料理の具材選択](dish-customisation.md)にまとめています。

### 同じ料理の種類をまとめて選ぶ

うどん、そば、パスタ、みそ汁、オムレツなどは、同じ料理を1つの入口へまとめています。詳細の「バリエーション」で種類を選ぶと、対応する材料と栄養、作り方、基準量へ切り替わります。記録画面でも「メニュー」に続く「バリエーション」で選べます。「カルボナーラ」のような具体的な名前でも検索できます。ご飯やおにぎり、寿司の握り・巻物、お茶やコーヒーも同じ考え方で選べます。カップ麺やレトルトは手作りと別の入口です。

手作りと即席、レトルトなどは区別して選べます。料理をまとめて表示しても、既存のレシピや過去の記録を削除することはありません。対象とまとめ方は[バリエーションの整理](menu-variations.md)をご覧ください。

### 記録を日付や範囲でリセットする

選択日の入力欄にある「選んだ日の入力をリセット」は、その日の記録を対象にします。日付範囲を指定するときは下部の「記録をリセットする」を開きます。範囲の最初と最後の日はどちらも対象です。日付を未来まで広げると、これからの予定も対象になるので期間を確かめてください。

範囲指定では「食べた記録と予定」「食べた記録だけ」「予定だけ」から選びます。対象の食事件数、料理数、完了チェックの日数を表示し、実行前にもう一度確認します。メモだけの記録も食事1件として数えます。

「予定だけ」では食べた記録と完了チェックを保ちます。実績を含むリセットでは範囲内の完了チェックも外します。料理が0件でも完了にしてある日は、この解除の対象です。自分のDB、設定、手持ちの食材は残ります。

実行直後は「直前のリセットを戻す」で戻せます。別の内容を保存するかページを読み込み直すと、この取り消しは使えません。残したい記録は事前にJSONへ書き出せます。

### カップ麺やレトルト食品を記録する

「調理・提供形態」を「即席」にすると、ラーメン、うどん、そば、焼きそばなどからカップ麺や袋麺を探せます。入力する1食・1袋は、画面に表示される乾燥製品の量や湯を含む基準に合わせます。乾燥重量と調理後の量を混ぜないよう説明を確認してください。

レトルトのカレーライスや丼は「レトルト」から探せます。収録例はご飯を含む1皿です。例えば「ご飯180g＋レトルトの具200g」という基準なら、ご飯も含めて1皿として記録します。ご飯を別に追加したり、具だけの栄養表示を1皿全体の値として使ったりしないでください。食べた量や商品が違う場合は手入力で調整できます。

ハンバーガーは「ファストフード」、市販サンドイッチは「そのまま」でも絞り込めます。市販品には銘柄や店舗を指定しない一般例と、公式表示に基づく商品例があります。原材料やアレルギー情報が未確認のものには確認の案内を表示し、自動提案には使いません。実際に食べたものをカレンダーへ記録することはできます。

商品の表示が分かる場合は「見つからない食事を入力」から名前、基準量、栄養や原材料を登録し、自分のDBへ保存できます。収録されている市販品の例を記録しただけで、原材料の確認が済んだ扱いにはなりません。

### お菓子やスイーツを記録する

間食の「種類」ではチョコレート、飴・キャラメル・ラムネ、グミ、クッキー・ビスケット、スナック菓子、せんべい・米菓、ドーナツ、ケーキ、和菓子、アイス・氷菓から探せます。ポッキーなどの商品例も追加しています。果物、ナッツ、ヨーグルト、チーズ、ホットスナック、補食はそれぞれ別の種類です。

1個や1袋の量は商品によって異なります。メニュー詳細の基準量を確認し、食べた量に合わせて入力してください。商品の栄養表示を使う例でも、原材料やアレルギー情報が未確認なら自動提案には入りません。詳しい参照先は[菓子・スナックの出典](confectionery-sources.md)と[スイーツの出典](dessert-sources.md)をご覧ください。

### プロテイン・補食・お酒を記録する

飲み物の種類には「清涼飲料水」「プロテイン飲料」「お酒」を用意しています。プロテインはソイとホエイを区別し、粉末を水で割る場合と牛乳で割る場合も別に選べます。粉末のgと液体のmlを足して完成容量としないため、粉末の調製例は配合全体を1杯として扱います。牛乳割りには牛乳の栄養とアレルゲンも加えます。

間食の「補食・栄養補助食品」にはバーやゼリーなどの記録例があります。商品に表示される本数・個数・容量と画面の基準量を確かめて入力してください。

商品例の栄養は公式表示を確認した時点の参考値です。参照先と基準量は[酒・飲料・補食の出典](performance-food-sources.md)にまとめています。味や容量、商品の仕様が変わる場合があるため、購入した包材の表示を優先してください。成分表示が範囲になっているものや不明な成分は、勝手に平均や0へ置き換えません。原材料やアレルギー情報が未確認の商品は自動提案に使いません。

お酒は飲んだ量を記録するための項目です。献立の候補や飲み物の自動提案には入りません。ストレートの基準量に氷や割り材は含まれないため、ハイボールなどは表示する配合を確認してください。

### 1日の記録を完了する

その日に飲食したものをすべて登録したら「この日の飲食をすべて記録した」にチェックします。最近の平均には、この確認が済んだ日を使います。入力途中の日を、摂取量が少ない日として数えないための操作です。

食事や飲み物の入力を忘れていた場合は内容を追加・修正し、記録がそろっていることを確認してください。予定を入れただけでは1日の摂取量を記録したことになりません。

## DBにない食事を入力する

「見つからない食事を入力」から料理名、種類、量を入れます。外食や市販品も記録でき、栄養・材料・作り方は分かる範囲で補います。手入力では基準量と単位も設定できます。例えば基準を100gにして100g当たりの栄養と材料を入力し、50g食べた場合は「食べた量」を0.5倍とします。基準を1人分にした場合も、半分なら0.5倍です。

商品の栄養成分表示が分かる場合は入力できます。空欄は不明として残し、0を入れた場合だけ「0と分かっている」値として扱います。料理名やメモから栄養を推測する機能はありません。

全材料と分量を登録した場合は確認欄を選び、「材料から栄養の概算を入力する」を押せます。入力欄が概算値に変わるので、商品の値が分かれば後から修正してください。ボタンを押さなければ空欄を自動計算しません。

アレルギー情報は別に確認します。含まれる登録アレルゲンを選び、確認できたときにチェックします。全材料が分かるメニューでは、材料と原料に登録されたアレルゲンも引き継ぎます。

「自分のデータベースにも保存する」を選ぶと、次回からメニューとして呼び出せます。選ばなければその食事だけの記録です。自分のDBはブラウザー内に保存し、公開レシピ集へ送信しません。

アレルギー情報が未確認のメニューは自動提案しません。材料全体が未確認で追加の除外食材がある場合も候補から外します。実際に食べた事実としてカレンダーへ残すことはできます。

自分のメニューは「メニュー」タブのDB管理から削除できます。DBを削除しても記録済みの料理は残ります。記録時点の栄養と材料を保存するため、後からメニューを変えても過去の数字が勝手に変わることはありません。

## 栄養の量と最近の傾向を見る

「栄養」で日付と期間を選びます。1日・7日・30日を切り替え、エネルギー、たんぱく質、脂質、炭水化物、食物繊維、食塩相当量の6成分を確認できます。摂取量に使うのは「食べた」の記録だけです。

不明な成分を含む場合は、分かっている合計と不明分を区別します。数字が小さくても食事全体の量が少ないとは限りません。記録がない食事も食べなかったとは判断しません。

最近の平均では「この日の飲食をすべて記録した」を選んだ日を使います。栄養が不明な日は、その成分の平均から除きます。例えばエネルギーが分かる日が5日、食物繊維が分かる日が3日なら、それぞれ5日と3日で平均します。成分ごとの対象日数も確かめてください。記録がそろった日がなければ平均を確定しません。

家庭向けレシピの栄養は食品成分表と材料の分量から求めた概算です。商品の記録例には公式の栄養表示を使うものもあります。商品の配合や調理方法、汁の残し方などで変わるため、各メニューの基準量と出典も確認してください。根拠は[栄養値の出典](nutrition-sources.md)にまとめています。

## 比較の目安を自分に合わせる

「設定」で「プロフィールから参考値を選ぶ」を選びます。18歳以上の年代、基準表で参照する性別区分、普段の活動量を指定して保存すると、厚生労働省の2025年版食事摂取基準を参考に比較値を選べます。未選択の項目はアプリが推測しません。

活動量は、座って過ごすことが多い「低い」、通勤・通学や家事などで動く「ふつう」、活発な仕事や運動習慣がある「高い」から選びます。75歳以上の「高い」には原表の値がないため、自動の参考値を作りません。

| 成分 | 比較する目安の意味 |
| --- | --- |
| エネルギー | 参照体位に対する推定値。個人の体格から必要量を求めた値ではない |
| たんぱく質 | 推奨量を主な参考値にする |
| 脂質・炭水化物 | エネルギー比率の範囲をgへ換算する。中央の値は表示や提案のための参考値 |
| 食物繊維 | 目標量は「以上」 |
| 食塩相当量 | 目標量は「未満」。不足分を足すための数値ではない |

「自分で数値を設定する」も選べます。初期値は表示を試すための参考値です。プロフィールも、体格による調整、妊娠・授乳中、18歳未満、治療用の自動計算には対応していません。1日分や入力途中の記録から健康状態を診断する表示ではありません。

詳しい表と換算は[年代・性別・活動量による目安の出典](dietary-reference-sources.md)を参照してください。

## 献立を作る

「献立」で開始日、日数、買い物の人数、食事区分を選びます。「朝・昼・夕の3食」なら指定した日の3食をまとめて作ります。例えば3日分は9食です。朝食・昼食・夕食・間食のどれか1つだけでも作れます。期間は1〜7日、買い物用は1〜8人分です。条件に合う候補が足りないときは、途中までの献立を予定として保存せず、見直す条件を案内します。

主食は「主食の決め方」で選びます。

| 決め方 | 動き |
| --- | --- |
| 献立に合わせる | 食事区分や主菜に合わせて種類を選び、各メニューの基準量を使う |
| 種類と量を指定する | 具体的な主食と量を決め、まとめて作る各食に使う |
| 別の主食は付けない | 主菜などとは別に主食を追加しない。麺や丼などに含まれる主食まで取り除く設定ではない |

飲み物は種類とメニュー、量を指定します。ご飯はg、おにぎりは個数、飲み物はmlなど、選んだメニューの単位に合わせます。指定した量は提案の栄養、カレンダーの予定、買い物の必要量にも使います。

パスタやカレーライス、丼など一品で主食を含む料理を選んだ場合は、別のご飯や主菜を重ねない構成を使います。間食では間食メニューを中心に選びます。

アレルギーや追加の除外食材を先に確認し、ジャンルや比率、気分、優先したい食材を指定できます。ジャンルや気分は希望で、食材を避ける条件が優先です。必要な候補がなくなっても除外を自動で取り消しません。加工品や調味料は商品表示も確認してください。

「献立はどうやって選ぶ？」を開くと基準を確認できます。アレルギーと除外食材は必ず守る条件です。ジャンルや比率、気分は希望として扱い、該当する候補がなければ別の候補を使う場合があります。最近食べた料理や今回すでに提案した料理の繰り返しを避け、優先食材と手持ちの食材も参考にします。

栄養の順位付けにはエネルギー、食塩相当量、たんぱく質、食物繊維を使います。最近の記録からエネルギーと食塩の摂りすぎを避け、たんぱく質と食物繊維が少ない場合は補いやすい候補を優先します。脂質と炭水化物は振り返り画面で確認できますが、候補の順位には使いません。

最近の栄養は記録を完了した日を参考にし、当日すでに食べた内容も対象の食事より前の分を使います。予定や後の食事を摂取量へ加えません。今回作る複数食の間では料理の重複も調整します。

収録したテイクアウトや即席食品、市販の菓子・スイーツのうち原材料やアレルギー情報が未確認のものは、固定指定や差し替えでも自動提案へ戻りません。食べたものとして記録することはできます。商品表示を確認して自分のDBへ登録した場合は、材料やアレルギーなどの検査を通れば候補になります。お酒は常に記録専用です。

提案した各食の「この食事の主食を調整」では、ほかの食事を変えずに主食と1人分の量を変更できます。「この食事に反映」で栄養と買い物も更新します。麺や丼など主食を含む一品料理には別の主食を重ねず、量はカレンダーへ登録してから調整します。

「料理を替える」で別の候補を探せます。料理のチェックを外すと、その日の予定保存と買い物から外れます。料理名を押すと材料と作り方を開けます。内容を確認して「予定としてカレンダーへ」で登録し、食べたら実績に切り替えてください。

提案は目安に合う候補を選びやすくする仕組みで、1日の全成分をぴったり合わせる最適化ではありません。参考にした理由も確認できます。作成中の提案は予定として保存するまで再読み込み後には残りません。

## 必要なものを買い物リストへまとめる

「買い物」で手持ちの食材と調味料を選び、家にある量を登録します。同じ食材を再登録すると量を更新します。単位は食材ごとに決まっており、生米・炊飯済みのご飯、乾麺・ゆで麺などの状態も区別します。

リストは「いま提案されている献立」と「カレンダーの予定」を切り替えられます。最初の日と日数を選ぶと、必要な材料をメニューの量と人数分にまとめ、手持ちの量を食材ごとに一度だけ差し引きます。「食べた」実績は対象外です。

カレンダーは自分1人の記録です。例えば4人分の夕食を作って自分がご飯150gを食べる場合、カレンダーは150g、買い物はその材料を4人分として計算します。

材料が未登録、全体が未確認、現在のDBにない材料を含む場合はメニュー名を知らせます。表示された材料だけで必ず足りるとは考えず、不明分を確認してください。

ハンバーガーや市販サンドイッチは完成品の個数で集計します。例えば1人1個を2人分なら、完成品を2個買う量になります。肉やパンへ分解して買い足す計算ではありません。レトルトのご飯込みメニューは、具と炊飯済みのご飯を分けて必要量に加えます。袋麺やカップ麺では登録された乾燥製品の量などを使います。

買う商品の種類と分量が分かる場合は、原材料の詳細が未確認でも商品量を集計できます。その場合も「原材料や商品の確認が必要なメニュー」の案内は残ります。買い物の数量が表示されたことと、アレルギー情報を確認できたことは別です。手入力でも、必要な商品と分量がそろっていることを確認して登録してください。

購入済みチェックは目印です。在庫の数値を変えるものではありません。使った分や買い足した分は自分で更新します。在庫だけを直す場合は提案を残して再集計します。「買うものをコピー」も使えます。完成品を個で扱う例はありますが、gで管理する食材を袋・パック単位へ切り上げる計算や支払額の計算はしません。

## 記録を保存し、別の端末へ移す

「設定」から「データを書き出す」でJSONを保存できます。「データを読み込む」で形式を検査し、確認後に現在のデータを置き換えます。追加ではなく置き換えなので、必要なら先に書き出してください。不正なファイルで現在の記録を上書きしません。

v3.0.0〜v3.6.0の保存データやJSONはv3.7.1でも読み込めます。保存形式は引き続きversion 3です。新しい主食設定がないデータも受け入れ、以前の主食指定を引き継ぎます。過去の食事の料理名や量、栄養は記録時点の内容を保ちます。以前の店舗名も自動で改名しません。新しく選ぶメニューには現在の表示名、分類、基準量を使います。

旧「献立ノート」のv1・v2の保存やJSONも引き継げます。アレルギー、除外食材、好み、記録を残し、プロフィールは未選択、記録を完了した日は未確認で始めます。旧保存領域を読み込み時に消すことはありません。

食事の記録、プロフィール、自分のDB、在庫や設定はブラウザー内に保存します。個人データをGitHubや共通DBへ送信せず、別の端末との自動同期もありません。書き出したJSONには食事やアレルギーの情報が含まれるため、共有先も確認してください。

JSONは2MB以下、食事の記録は5000件、マイレシピは500品までです。件数内でもサイズ制限があります。保存できない場合は画面に案内するため、閉じる前にデータを書き出してください。

「食事の記録をすべて削除」はカレンダーが対象です。自分のDBや設定も消す場合はブラウザーでこのサイトの保存データを削除します。

## メニューやPythonのコードを見てみる

「メニュー」の上のボタンは「すべて → 主食 → 主菜 → 副菜 → 汁物 → 飲み物 → 間食」の順です。料理名や材料でも検索できます。ひらがな・カタカナの違い、半角・全角、収録語の漢字や別表記をそろえて探します。例えば「唐揚げ／からあげ／カラアゲ」「焼売／しゅうまい／シューマイ」「焼き鳥／やきとり／ヤキトリ」を同じ語として扱います。記録タブのメニュー検索と、使いたい食材・避けたい食材の検索でも使えます。空白で「鶏肉 しょうが」と分けると両方を含む候補へ絞り、語順は問いません。料理名に一致する候補を先に表示し、材料だけに含まれる候補はその後に続きます。未知の漢字を自動で読む機能ではないため、見つからない表記は別の言い方でも試してください。

| 区分 | 選ぶ流れ |
| --- | --- |
| 主菜・副菜 | 食材カテゴリ → 調理法 → 個別メニュー |
| 主食・汁物・飲み物・間食 | 種類 → 個別メニュー |
| すべて | 全メニューを表示。食材カテゴリや調理法を指定すると主菜・副菜を絞り込む |

食材カテゴリには肉、魚介、野菜・いも、卵、豆・豆腐、きのこ、海藻などがあります。調理法では揚げ物、刺身、焼き物、煮物、煮込み、鍋料理、炒め物、蒸し物、和え物、サラダなどを選べます。唐揚げ、フライ、カツ、コロッケは「揚げ物」の中で料理名から選びます。ジャンルと調理・提供形態も組み合わせられます。「手作り」や「レトルト」は調理法とは別で、栄養の良し悪しを示す分類ではありません。

枝豆は間食ではなく副菜として探します。冷奴、卯の花、ひじき煮、ポテトサラダ、春雨サラダ、煮物なども食材と調理法から選べます。お刺身は「主菜 → 魚介 → 刺身」から、まぐろ赤身・中トロ、サーモン、ぶり、たい、かつお、あじ、いか、ゆでだこ、ほたて、盛り合わせを探せます。

v3.2.0では肉野菜炒めや焼き鳥、ムニエル、シチュー、鍋料理などの主菜と、丼やドリア、サラダ、温野菜、揚げ出し豆腐、スープなど計87品を追加しました。食堂やレストランで見かける料理を参考にした家庭向けの例です。店の商品の量や栄養をそのまま再現するものではありません。[メニューの調査と分類](menu-research.md)で参照先と考え方を確認できます。

v3.4.0では水餃子、春巻き、グリーンカレー、タンドリーチキン、焼き鳥、焼き肉、うなぎ、天ぷらなどを補いました。v3.5.0では菓子・スイーツに加え、肉豆腐、もつ煮、ぼっかけ、そばめし、牛タン塩の家庭向けの例も追加しています。v3.6.0ではご飯のお供を単品で追加し、サラダの組み合わせも選べるようにしました。v3.7.0では肉じゃがやお好み焼きの具材選択を加え、同じ料理の種類を詳細へまとめました。料理の調査は[定番料理の追加調査](menu-research-v3-4.md)と[家庭向け料理5品の出典](comfort-food-sources.md)をご覧ください。

惣菜や持ち帰り料理の見出しは「焼き鳥・もも（たれ・テイクアウト）」など一般的な料理名です。参照した店舗・商品、規格、基準量、公式URLはメニュー詳細の出典と[購入品の出典](takeaway-food-sources.md)へ残しています。栄養値は出典の商品を参考にした記録例で、同じ料理すべてに当てはまる値ではありません。手元の商品と量が違う場合は手入力で調整してください。

料理名を押すと材料と作り方を開けます。詳細上部の「カレンダーに追加」で日付、食事区分、予定か実績か、量を指定し、「この料理を記録に追加」を押すと記録へ移ります。量はg・貫・切れなど、そのメニューの単位で入力します。手作りでは材料に加え、下ごしらえ、加熱の進め方、火の通りや仕上がりの目安を表示します。料理に合わせた工程数で、簡単な料理を無理に3工程へ増やす構成ではありません。カップ麺、レトルト、ファストフード、購入済みの食品には作り方の番号を付けず、商品と量、栄養の基準や出典を示します。調理・再加熱が必要なら商品の表示に従ってください。

アレルギーや除外食材を設定している場合は、その条件を一覧にも反映します。原材料が未確認の市販品も一覧から外すため、見つからないときは条件を確認してください。食べた事実を残すときは「記録」から登録できます。学生の元作品は[AI献立スマートシェフ](https://cish25155-prog.github.io/SmartChef/)から開けます。

## 栄養の見積もりを確認する

家庭料理の栄養は、食材・調味料の代表値に使用量を掛けて人数で割った概算です。例えば牛肉の薄切りは輸入牛の肩ロース脂身付き、豚肉の薄切りは豚肩ロース脂身付き、鶏もも肉は皮付きの値を使います。豚ばら・豚ロース・牛ひき肉・豚ひき肉などはそれぞれ別の値です。合いびき肉はレシピ内の牛肉と豚肉の使用量を合わせて計算します。

メニューの詳細にある「栄養の見積もりに使う食材・部位」を開くと、各材料の成分表の対応と補完の根拠を読めます。酒やみりんの脂質のような微量成分も計算に含め、クミンやターメリックには海外の公的成分表の一般値を用いています。油はmlから重量へ換算し、卵は1個の可食部50gとして扱います。

肉から落ちる脂や残した煮汁の量までは計算していません。過去の記録を今回の概算で自動更新することもありません。未確認の商品や手入力の空欄は不明として残ります。詳しい数値と仮定は[栄養値の出典と換算方法](nutrition-sources.md)をご覧ください。
