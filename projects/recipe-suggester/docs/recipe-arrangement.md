# 材料の編集・追加とオリジナルレシピ

既存料理の「材料を編集・追加してアレンジ」では、元レシピ1人分の材料を減らす、削除する、別の食材へ置き換える、食材を追加する操作ができます。元レシピを変更せず、1皿＝1人分の新しい料理として記録します。保存を選ぶとマイメニューにも残ります。

「元の材料」には1人分の量を表示します。数量を0にするか「削除」を押すと使わない材料になります。「食材を替える」を押し、下の食材ピッカーで種類と使用量を選んで「この食材に置き換える」を押すと、その材料を置き換えます。「元に戻す」で各材料の変更を取り消せます。油の半量、チーズ抜き、鶏もも肉から鶏むね肉への変更などに使えます。入力が空欄・負数の間は登録できません。材料をすべて削除した料理は作れません。

材料を変更した場合は、変更後の材料全体から栄養と買い物用の分量を再計算します。材料から由来するアレルゲンや食品群も再計算するため、確認済みの料理から乳製品をすべて除くと、それらに由来する乳アレルゲン表示も外れます。レシピに固有の追加アレルゲンは残します。元料理のアレルギー情報が未確認なら未確認の状態と元のアレルゲン表示を引き継ぎます。

原材料が未確認の料理や、商品表示・スープ摂取量などの集計済み栄養値を持ち、材料の栄養合計と対応しない料理では、材料ごとの減算を確定できません。この場合は元材料の編集を無効にして理由を表示し、食材の追加を利用できます。ラーメンのスープ摂取量などは、その料理の専用画面で選び直してください。材料合計と一致する手入力栄養値の料理は編集できます。

元の調理手順は引き継ぎます。材料を変更した場合は、元の手順に残る食材名を変更後の材料へ読み替える案内を追加します。加熱時間や方法が異なる肉・魚へ置き換えた場合は、変更後の食品に適した十分な加熱が必要です。

「オリジナルレシピを作る」では料理名、区分、使う材料と量を登録します。作り方も任意で入力できます。食材はデータベース内の肉、魚介、野菜、きのこ、卵・豆、乳製品、穀類、果物、調味料から選べます。

量は可食部のg数を基本にします。元の単位がmlや個でも、データベースに重量・密度の換算値がある場合はgで入力し、栄養計算と買い物リストでは登録済みの単位に戻します。換算値が未登録ならその食品の元の単位を表示します。骨、殻など食べない部分は入力量から除きます。

食材はDBに記載された状態の代表栄養値をそのまま合計する概算です。加熱による栄養損失、油の吸収、煮汁の残りは自動補正しません。追加だけを行った場合は元レシピが持つ手入力の栄養値も保持し、追加分だけを一度加算します。元の栄養値が不明の成分は、食材を足しても不明のままです。

元の料理の原材料・アレルギー確認が未完了なら、その状態を引き継ぎます。食材を足しただけでは確認済みになりません。元料理の買い物用構成も不明なら、料理全体の買い物リストは未確定として表示します。保存・記録した料理はその時点の材料と栄養を持ち、後で元のレシピや食材データを更新しても過去の記録は変わりません。

開発用の `buildRecipeArrangement` は従来の `additions` と互換です。元材料の編集は `ingredientEdits: [{id, amount, unit?, replacementId?}]` を渡します。`id` は元材料、`replacementId` は任意の置き換え先、`amount` は変更後の1人分の使用量で、0は削除を表します。`arrangementBaseIngredients` は入力用の1人分の量、`arrangementEditAvailability` は編集可否と表示用理由を返します。
