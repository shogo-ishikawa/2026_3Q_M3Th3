# LUMENの仕組みと学生作品との対応

対応版：v1.0.0

## 発想を引き継ぐ

学生の提出Notebookは2つのコードセルで構成されます。前半は音の高さと大きさを色・形・数値へ対応させる比較実験、後半は声やマウス操作に反応するCanvasアートです。LUMENはこの二つを作品の軸として引き継ぎ、ブラウザー上で直接操作できる形へ発展させています。

| 学生版の処理 | 公開版で引き継ぐ点 | 発展させた点 |
| --- | --- | --- |
| `compute_all_three_targets()` | 音高と音量の正規化、HSVの色、丸と星、1〜100の値 | JavaScriptへ移植し、対応を独立した関数に分離 |
| 4つの音の比較 | 880/165Hzと95/20%の組み合わせ、対応の反転 | ブラウザー内の実験室で操作 |
| `generate_sound_wave()` | 基本波と倍音を組み合わせる発想 | ブラウザーの音声処理へ接続 |
| `Particle`と`addParticles()` | 上下位置で色と形を変え、操作速度で光を強める | 複数の指、場面ごとの表現、描画量の上限に対応 |
| マイクによるオーロラ | 音の変化を色や光へ伝える発想 | 音高推定と入力の開始・停止を整理 |

学生の氏名や学籍番号を公開用の画面やサンプルに使いません。提出原版は学内向けのBoxで配布し、この公開リポジトリやZIPには同梱しません。公開する`lumen_lab.ipynb`は学生の対応式をPythonの標準機能で書き直した発展版の教材です。元の提出物と公開版の機能を区別して管理します。

## 音から色・形・数値へ

実験室は元コードの130〜1000Hzと10〜100%を使います。入力を0〜1に正規化した値をそれぞれ`p`と`v`とすると、基本の対応は次の通りです。反転時は`p`と`v`をそれぞれ`1-p`、`1-v`へ置き換えます。

| 対象 | 対応 |
| --- | --- |
| 色相 | `0.64 - 0.62 * p`。青系から赤系へ変化 |
| 彩度 | `0.28 + 0.72 * v` |
| 明るさ | `0.30 + 0.70 * v` |
| 形の波・頂点数 | `4 + 12 * v`を整数へ丸める |
| 星の鋭さ | `0.60 * p` |
| 数値 | `1 + 99 * (p + v) / 2`を整数へ丸める |

形の外側の半径は0.68で固定します。`p < 0.35`なら200点の波打つ丸い輪郭、それ以外は外側と内側の点を交互に並べる星形です。JavaScriptとPythonでちょうど中間の値の丸め方が異なるため、元のPythonの`round()`に合わせた処理を用います。HSVから16進色へ変換する際も元コードの切り捨てを引き継ぎます。

学生版の前半セルには`math.pi`を使う一方で`import math`がないため、星形を選ぶ経路で実行エラーになります。提出原版は学内資料として保持し、公開するJavaScript版では`Math.PI`を使ってこの問題を解消します。公開用のPython教材でも必要なモジュールを明示して読み込みます。

色と音の対応は作品の設計です。感覚の普遍的な法則として示すものではありません。4パターンや反転を用意することで、対応を変えたときの印象を比べられるようにします。

## 音を解析する

`audio.js`は音源やマイクをWeb Audio APIへ接続し、解析用のデータを`core.js`へ渡します。時間方向の波形から音の大きさを求め、周期のある信号についてYIN法で基本周波数を推定します。これは信号を少しずつずらしたときの違いから周期を探す方法です。スペクトルの重心は、周波数ごとの強さから求める別の特徴量です。

| 特徴量 | 意味 |
| --- | --- |
| `rms` | 波形の二乗平均平方根。振幅の目安 |
| `level` | 作品の反応へ使う0〜1の相対的な大きさ |
| `pitchHz` | 周期から推定した基本周波数。未検出時は`null` |
| `confidence` | 周期を持つ信号としての推定の確かさ |
| `centroidHz` | スペクトルの重心。音の明るさに関わる特徴の一つ |

学生版の後半セルはFFTで最も強い周波数ビンを選び、その番号を色へ対応させています。この最大ビンは基本周波数と一致するとは限らず、倍音が強い音や複数音の入力では特に異なります。公開版では基本周波数の推定とスペクトルの特徴を分け、無音や信頼度の低い信号を「0Hzの声」として扱わないようにします。

音量は端末、マイク、音源の振幅に依存する相対値です。校正した音圧レベルや騒音の測定値ではありません。複数の声や楽器が混ざる信号から、全ての音高を同時に分離する機能もありません。

## 光を描く

描画ではCSSピクセル単位の座標を使い、表示先の解像度へ合わせてキャンバスを調整します。描画用の倍率と粒子数には上限を設けます。フレーム間の時間差も制限し、タブを戻した瞬間に粒子が大きく飛ぶことを抑えます。

元の上下位置に応じた色と形、速度に応じた明るさを保ちながら、場面ごとに光の重なり方を変えます。「光の庭」は粒子と花、「水の記憶」は波紋と灯、「オーロラ」は幾重の幕を中心にします。デモは一定の規則から仮想の操作と入力信号を作るため、音源がなくても体験できます。デモの信号はマイクを測定した値とは区別します。

光は生成後に減衰し、寿命を終えたものを取り除きます。複数の指は別々の入力として追跡し、指を離したら追跡対象から外します。「動き」が0のときは背景の時間変化を止め、音や手の操作には反応します。「一時停止」は時間の進行を止める操作です。動きを減らす端末設定では静止表示から始めます。

## 画面と処理を分ける

| ファイル | 責務 |
| --- | --- |
| `core.js` | 数値変換、基本周波数とスペクトルの解析、デモ信号 |
| `audio.js` | 音声の入出力、音源の読み込み、開始・停止、再生ノードの後始末 |
| `renderer.js` | キャンバスへの描画と光の状態 |
| `app.js` | 操作画面、入力、描画ループ、各処理の接続 |
| `lumen_lab.ipynb` | 色・形・数値の対応式を学ぶ公開用のPython教材 |

マイクの使用は利用者の操作とブラウザーの許可を経て始めます。マイク入力をスピーカーへ直接接続せず、停止時は入力トラックを止めます。音源の切り替えや連続操作で古い読み込みが後から完了しても、その結果が新しい入力を上書きしないようにします。

音の出力は初期状態でOFFです。音源の再生と実験室の発音は、利用者の操作を受けて出力をONにします。出力をOFFへ戻しても音源の分析は続けられます。ページが非表示になった場合は光の進行を止め、音源の再生を一時停止します。読み込み済みの音源は保持しますが、マイク、許可待ち、音源の読み込み中の処理は取り消します。

音源はブラウザー内で読み込みます。サーバーへの音声送信、録音の保存、アカウント登録は行いません。画面の保存はキャンバスからPNGを作る処理で、音声データを画像へ付加しません。

## 授業で変更しやすい箇所

まずは`core.js`の正規化と対応式を変更すると、少ないコードで違いを確かめられます。変数は調整する値、配列は点やプリセットの並び、条件分岐は丸と星の切り替え、繰り返しは輪郭を作る点の生成に対応します。

Pythonで取り組む場合は、公開用の`lumen_lab.ipynb`で入力を変えて返り値を確認するところから始められます。`math`と`colorsys`で色や座標を計算し、リストと繰り返しで形を作り、SVGで表示します。標準の`wave`では0.6秒の合成音を作ります。音高だけを変えてRGB値を並べる、形の座標を別の方法で描く、反転前後の数値を比較する、といった小さな課題へ分けられます。入力・計算・表示を別の関数にすると、アートの変更とプログラムの変更を結び付けて理解しやすくなります。
