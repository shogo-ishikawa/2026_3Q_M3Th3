# ダミーデータと期待する結果（M3 検索・M5 機密の判定・M1 改名の提案）

M3 エピソード記憶検索の3つの例「青いグラフ」「Slackで貰った」「先週の予算資料」、M5 の機密の判定、
M1 の改名の提案を、自分の PC で試すためのダミーデータです。ファイルは `pip0/demo_data.py` のコードがその場で作ります。
リポジトリーには、画像・文書などのデータを置いていません（外部のデータも使いません）。
デモは、検索と機密の判定を期待と比べます。M1 の改名の提案は表示するだけで、期待とは比べません（8節）。

## 1. 動かし方

`projects/pip0` で、仮想環境に入ってから実行します（[README.md](../README.md) の 3-1）。

一時フォルダーの中に、新しい空のフォルダーを作って試すとき：

```bash
python -m pip0 demo
```

作ったダミーのファイルを後で見たいときは、空のフォルダー（なければ作ります）を指定します。
**リポジトリーの外の場所**にしてください（リポジトリーの中に作ると、「社外秘」の名前のダミーのファイルなどを、
Git に登録してしまうおそれがあります）。

macOS・Linux：

```bash
python -m pip0 demo --dir ~/pip0-demo
```

Windows：

```bat
python -m pip0 demo --dir C:\pip0-demo
```

macOS・Linux のターミナルで `C:\pip0-demo` と書くと、`\` が消えて、今のフォルダーの中に `C:pip0-demo` という
フォルダーができます。

`python -m pip0 demo` は、`pip0/cli.py` から `demo_data.run_demo()` を呼び、その後に M1 の改名の提案（8節）を表示します。
Python から直接呼ぶこともできます（`projects/pip0` で Python を起動します。この方法では、M1 の改名の提案は表示されません）。

```python
from pathlib import Path

from pip0 import demo_data

report = demo_data.run_demo(Path.home() / "pip0-demo")  # 空のフォルダー（なければ作る）。リポジトリーの外にする
print("\n".join(demo_data.report_lines(report)))        # 結果と、期待どおりかどうかを表示する
```

自動テストは `python -m pytest -q tests/test_demo_data.py` です（日本時間の 2026-10-29（木）10:00 に固定して確かめます。
日時の決め方と「ほかにも試せる検索」は、月の初め・月の終わり・年の初めの日付でも確かめます）。
このテストは、Windows の Python では、今は動きません（[README.md](../README.md) の 3-1 の注意）。

`run_demo()` がすること：

1. ダミーのファイルを作る（`create_demo_dataset`）。一覧を、作ったフォルダーの `pip0-demo-manifest.json` に書く
2. 最終更新日時を付け、入手経路の記録をまねる（ブラウザー拡張の記録、Windows の Zone.Identifier）
3. 索引を作る（`scanner.scan_folder`）
4. 解析する（`analysis_queue.analyse_file` と `store_result`。`throttle.HeavyGate` を通す）
5. 3つの検索（`search.search`）と「ほかにも試せる検索」（7節）、機密の判定（`hazard.evaluate_items`）を行い、
   期待（`expected_results`、`other_expected_results`）と比べる

### 安全のための決まり

- 本物のデスクトップ・ダウンロード・ドキュメント（OneDrive に移したものを含む）、本物の pip0 専用フォルダー
  （`%USERPROFILE%\pip0`）、Windows の「ダウンロード」の場所、pip0 のデータフォルダー（`%LOCALAPPDATA%\pip0`）の中には作りません。
- 空でないフォルダーには作りません（ほかのファイルと混ざらないように）。
- DB はメモリーの中だけに作り（鍵もメモリーだけ）、終わると消えます。作ったファイルは残るので、要らなくなったら
  フォルダーごと手で削除してください。
- **まねた条件**：解析は、代役の OS 連携（`FakePlatform`）で「電源接続中・180秒無操作」をまねて行います。
  実機の電源・アイドル状態を使ったものではありません。結果の表示にも、そのことを書きます。

## 2. 日時の決め方

日時は、デモを動かした時刻（`now`）を基準に決めます。いつ動かしても「先週」のファイルが先週になり、
古い予算の文書は「2か月前」の月の中（「先月」には入らない）になります。
「先週」は、検索と同じ決まり（`timeutil.find_period`、端末の現地時刻、週の始まりは `WEEK_STARTS_ON`）で決めます。

| 名前（コードの中） | 日時 | 例：2026-10-29（木）10:00 に動かしたとき |
| --- | --- | --- |
| `last_week_day2` | 先週の2日目（月曜始まりなら火曜）15:00 | 2026-10-20 15:00 |
| `last_week_day3` | 先週の3日目（水曜）14:30 | 2026-10-21 14:30 |
| `last_week_day4` | 先週の4日目（木曜）10:15 | 2026-10-22 10:15 |
| `two_weeks_ago` | 先々週の3日目（水曜）11:00 | 2026-10-14 11:00 |
| `two_months_ago` | 2か月前の月の15日 10:00 | 2026-08-15 10:00 |

### 作り方

- 棒グラフ：Pillow で、640×480 画素の白い背景に、黒い軸と目盛りの線、5本の棒を描きます（青は RGB 31,119,180、
  赤は 214,39,40）。文字は描きません（フォントを使うと環境で画像が変わり、フォントの利用条件も関わるため）。
- 写真のような画像：上から下へ明るくなる青の空、暗い緑の地面、ぼかした白い楕円（雲）、画素ごとの細かいむらを、
  乱数の種（2043）を決めて描きます。JPEG（品質 88）で保存します。
- PDF：番号の付いた部品を並べた最小限の PDF 1.4 をコードで書きます。本文は英語（PDF の標準フォント Helvetica を
  名前で指定するだけで、フォントのファイルは入れません）、文書情報のタイトルは日本語です。
- Word 文書（.docx）：`docProps/core.xml`（タイトル）と `word/document.xml`（段落）だけの最小限の Office 文書です。
- テキスト：UTF-8 で書きます。ZIP：中の日時を固定して作ります。
- 個人番号らしい数字：連番の11桁「12345678901」に、個人番号の検査用数字の計算で12桁目を付けた「1234-5678-9018」です。
  `sensitivity.is_valid_my_number` の確認に合格する、テスト用のダミーです。実在の人の番号として使わないでください。

同じ `now` なら、何度作っても同じ中身になります（`tests/test_demo_data.py` で確かめています）。

## 4. まねた入手経路

- **ブラウザー拡張の記録**（`IMG_2041.png`、`IMG_2042.png`、`document (1).docx`）：受け口（native_host）が書くのと同じ
  `provenance.store_download_event` で記録し、そのファイルに結び付けます。呼び出し元は
  `chrome-extension://pip0-demo-simulated/`（本物の拡張機能ではないことが分かる名前）です。
  - `IMG_2041.png`：ダウンロード URL `https://files.slack.com/files-pri/T0DEMO-F0DEMO01/img_2041.png`、参照元 `https://app.slack.com/`
  - `IMG_2042.png`、`document (1).docx`：ダウンロード URL `https://mail-attachment.googleusercontent.com/attachment/u/0/`、参照元 `https://mail.google.com/`
  - ダウンロード開始時のタブ（例：「予算2026 (Channel) - 研究室 - Slack」）も記録しますが、送信元には使いません。
- **Zone.Identifier だけ**（`F0A1B2C3.pdf`）：Windows がダウンロードしたファイルに付ける記録をまねて、代役の
  `FakePlatform.zone_identifiers` に `ZoneId=3`、`HostUrl=https://files.slack.com/files-pri/T0DEMO-F0DEMO02/download`、
  `ReferrerUrl=https://app.slack.com/` を入れます。ダウンロード日時の記録はないため、時期は最終更新日時で比べます。
- **記録なし**（ほかの6つ）：入手経路は「不明」のままです。推測で Slack 等にはしません。

## 5. 期待する検索結果

例の日付は、2026-10-29（木）10:00（日本時間）に動かしたときのものです。

### 「青いグラフ」

- 手掛かり：色「青い」（青と水色の割合の合計）、見た目「グラフ」
- **一致：`IMG_2041.png`**
- 一致の理由（数値は、この環境（Pillow 13.0.0）での例）
  - `色：青系 100%（画像の色解析）`
  - `見た目：グラフらしさ 1.00（背景が単色（73%）、色数が少ない（2色で95%）、縦横の長い線（軸）を検出、単色の長方形（棒）を5個検出）`
- 一致しないもの
  - `IMG_2042.png`：グラフらしさは 1.00 だが、色付きの部分は赤 100%（色：青系 0%）
  - `IMG_2043.jpg`：色付きの部分の 85% が青だが、グラフらしさが 0.15（写真）
- 数値は `analyse_image.py` の計算の決まりで変わることがあります。テストは「色：青系 ◯%（画像の色解析）」の形で
  `COLOUR_MIN_SHARE`（35%）以上か、「グラフらしさ」が `CHART_MIN_SCORE`（0.60）以上で「単色の長方形（棒）を5個検出」を含むかを確かめます。

### 「Slackで貰った」

- 手掛かり：入手経路「Slack」（「で」「貰った」は読み飛ばす）
- **一致：`IMG_2041.png`、`F0A1B2C3.pdf`**（新しい順）
- 一致の理由
  - `IMG_2041.png`：`入手経路：Slack（ブラウザー拡張の記録：files.slack.com からのダウンロード）`
  - `F0A1B2C3.pdf`：`入手経路：Slack（Windows のダウンロード元情報（Zone.Identifier）：files.slack.com）`
- 一致しないもの：`IMG_2042.png` と `document (1).docx` は Gmail から入手。記録のない6つは、Slack から入手したとは扱いません。
- 補足：`入手経路の記録がないファイルが 6 件あります（記録がないファイルを、Slack 等から入手したとは扱いません）`、`読み飛ばした言葉：で、貰った`

### 「先週の予算資料」

- 手掛かり：時期「先週」（2026-10-19（月）〜2026-10-25（日））、種類「資料」（文書の拡張子）、内容「予算」
- **一致：`document (1).docx`**
- 一致の理由
  - `時期：ダウンロード日 2026-10-22（ブラウザー拡張の記録）`
  - `種類：文書（.docx）`
  - `内容：タイトル・本文に「予算」`
- 一致しないもの
  - `document.docx`：「予算」はあるが、2か月前の月の文書（時期が違う）
  - `untitled.txt`：先週の文書だが、「予算」という語がない
  - `IMG_2041.png`：先週ダウンロードしたが、文書ではない
- 補足：`時期：先週（2026-10-19（月）〜2026-10-25（日））は、端末の現地時刻で調べました`、`読み飛ばした言葉：の`
- 時期は、ダウンロード日時（ブラウザー拡張の記録）→ pip0 が流入を確認した日時 → 最終更新日時 の順に、
  最初にあるもので比べます。

## 6. 機密の判定（M5）の期待

ドラッグしたときの警告（赤：機密、橙：機密か未判定）に使う判定です（`sensitivity.overall`）。

| ファイル | 判定 | 理由 |
| --- | --- | --- |
| `社外秘_打ち合わせメモ.txt` | 機密 | 名前に「社外秘」（解析していなくても分かる） |
| `申請書_下書き.txt` | 機密 | 本文に、検査用数字が正しい12桁の個人番号らしい数字（1件） |
| `F0A1B2C3.pdf`、`document (1).docx`、`document.docx`、`untitled.txt` | 非機密 | 解析済みで、機密の規則に当てはまるものはない |
| `IMG_2041.png`、`IMG_2042.png`、`IMG_2043.jpg` | 未判定 | 画像の中の文字は読み取らないため、中身で判定できない |
| `attachment.zip` | 未判定 | pip0 が中身を解析しない形式 |

未判定は、非機密とは扱いません（設定の `WARN_UNANALYSED` が True なら、橙色の警告を出します）。

## 7. ほかにも試せる検索

`run_demo()` は、次の検索も行い、期待（`other_expected_results`）と比べた結果を「ほかにも試せる検索」に表示します。

| 検索の言葉 | 結果 |
| --- | --- |
| 青い写真 | `IMG_2043.jpg` |
| 赤いグラフ | `IMG_2042.png` |
| メールで貰った | `document (1).docx`、`IMG_2042.png`（「メール」は Gmail と Outlook をまとめた言葉） |
| 2か月前の予算 | `document.docx`（いつ動かしても、2か月前の月の15日の文書） |
| 先月の予算 | 動かした日付で変わります（下を参照） |
| Slackで貰った写真 | 情報不足（写真には入手経路の記録がないため。Slack から入手したとは扱わない） |

「先月の予算」の結果は、予算案 `document (1).docx` のダウンロード日（先週の木曜日）が先月に入るかで決まります。

- 先週の木曜日が今月のとき（例：2026-10-29）：**該当なし**。
  一部一致として、時期だけが違う2つの予算の文書（`document (1).docx`、`document.docx`）を示します。
  先週の火曜日・水曜日や先々週の水曜日が先月に入る日（例：2026-10-06、2026-12-08）は、その日のファイル
  （「予算」の語はなく、時期だけが合うもの）も一部一致に並びます。デモは、2つの予算の文書が一部一致にあることを確かめ、
  ほかのファイルが一部一致に並んでいても期待どおりとします。
- 先週の木曜日が先月のとき（月の初めの数日。1日〜10日のうち、どの日までかは曜日で決まります。
  例：2026-11-01、2027-03-01）：**一致：`document (1).docx`**。

どちらになるかは `other_expected_results()` が動かした日付から計算し、デモの表示に、その日の「先月」の範囲も出します。

## 8. M1 の改名の提案（表示だけ。期待とは比べない）

`python -m pip0 demo` は、最後に、ダウンロードフォルダーの代わり（Downloads）にある、意味の分からない名前
（`rules.MEANINGLESS_NAME_PATTERNS` に当たる名前）のファイルについて、M1 の新しい名前の提案を表示します（ファイルは動かしません）。
**デモは、この表示を期待と比べません**（✓・✗ を付けず、最後の「結果：すべて期待どおりです」にも含まれません）。
改名に関係する規則や値を変えたときは、次の表と目で比べてください。

| 元の名前 | 提案する名前 | 例：2026-10-29（木）に動かしたとき |
| --- | --- | --- |
| `IMG_2041.png` | 先週の水曜の日付_青いグラフ_Slack.png | `2026-10-21_青いグラフ_Slack.png` |
| `IMG_2042.png` | 先々週の水曜の日付_赤いグラフ_Gmail.png | `2026-10-14_赤いグラフ_Gmail.png` |
| `IMG_2043.jpg` | 先々週の水曜の日付_青い写真_送信元不明.jpg | `2026-10-14_青い写真_送信元不明.jpg` |

- 日付は、ダウンロード完了日（ブラウザー拡張の記録）で、記録がなければ最終更新日時です。内容は、Office の文書のタイトル、

- 仕分け先（`rules.SORT_RULES`）は、この表示に出ません（試し方は [README.md](../README.md) の 5-4）。

## 9. 変え方（★）

- ダミーのファイルを足す・変える：`pip0/demo_data.py` の `demo_files()`。期待も `expected_results()`
  （「ほかにも試せる検索」は `other_expected_results()`）で直します。
  - `tests/test_demo_data.py` にも、ファイルの一覧と件数が書いてあります（10件のそれぞれの機密の判定、
    「入手経路の記録がないファイルが 6 件」、索引と解析の 10 件など）。これも合わせて直します。
  - 検索の結果（一致と一部一致）は、`SEARCH_MAX_RESULTS`（10件）で切られます。ファイルが10件を超えると、日付によっては
    「先月の予算」の一部一致から予算の文書が外れ、テストが失敗します（デモは動かした日だけを試すため、気づかないことがあります）。
    ファイルを10件までにするか、`demo_data.py` の `demo_config_overrides()` で `SEARCH_MAX_RESULTS` を増やします。
  - 確かめるときは、`python -m pytest -q tests/test_demo_data.py` を、ファイル全体で実行します（いくつかの日付で試すテストがあるため）。
  - 日時で答えが変わる検索の期待は、決まった日付で書かず、`manifest["now"]` から計算してください。
- 改名の提案に関係する値（`rules.py` の `MEANINGLESS_NAME_PATTERNS`、`settings.py` の `CONTENT_MAX_CHARS` など）を変える：
  デモは改名の提案を期待と比べないため、デモの最後は「結果：すべて期待どおりです」のままです。8節の表と目で比べ、
  `python -m pytest -q tests/test_naming.py` も実行します。
- 一致の決まりを変える：`pip0/settings.py` の `COLOUR_MIN_SHARE`、`COLOUR_MIN_COLOURFUL`、`CHART_MIN_SCORE`、`WEEK_STARTS_ON`、
  言葉の辞書は `pip0/rules.py` の `COLOUR_WORDS`、`VISUAL_KIND_WORDS`、`DOC_KIND_WORDS`、`SOURCE_WORDS`。
- 一致の理由の文：`pip0/search.py` の `check_time` などの関数。

## 10. 確かめたことと、確かめていないこと

- 確かめたこと（Linux の開発環境、代役の OS 連携）：ファイルの作成、索引、まねた入手経路の記録、解析、
  3つの検索の結果と理由、「ほかにも試せる検索」（月の初め・月の終わり・年の初めの日付と、先月のほかのファイルも
  「先月の予算」の一部一致に並ぶ日付を含む）、機密の判定、
  本物のフォルダーと空でないフォルダーを断ること（`tests/test_demo_data.py`）。
- 8節の表の例は、2026-11-01（日）にデモを動かした表示と同じであることを、目で確かめました（2026-10-29（木）と同じ週なので、
  日付も同じになります）。デモ自身は、改名の提案を期待と比べません。
- 確かめていないこと：Windows の実機での、本物の Chrome／Edge の拡張機能の記録、本物の Zone.Identifier、
  実機の電源・アイドル状態での解析、Windows の Python でのデモ。これらは実機で別に確かめる必要があります。

## 11. 出典と利用条件

- ダミーのファイルは、すべてこのリポジトリーの `pip0/demo_data.py` のコードが作ります。外部の画像・文書・フォントは使いません。
- 画像を作るのに Pillow（MIT-CMU（HPND）ライセンス）を使います。URL はデモのために作った架空のものです
  （`files.slack.com` などのホスト名は、送信元の判定の規則 `rules.SOURCE_RULES` を試すために使っています）。
- 学生の氏名・学籍番号などの個人情報は含みません。個人番号らしい数字は、上で説明した連番のダミーです。
