# FACEGATEの設計と開発

学生作品のFACEGATEを出発点に、公開URLから使えるブラウザ発展版を開発しています。学習済みモデルを端末へ読み込み、画像の処理をブラウザ内で行います。

## 配布する版の区別

| 版 | 扱い |
| --- | --- |
| `original/facegate-submitted.zip` | 学生が提出したZIPを変更せず保存。学生向けの配布に使用する |
| ブラウザ発展版 | 元作品を基に追加開発したHTML・CSS・JavaScriptのアプリ |
| `local/` | 公開用に保存・削除・起動などを調整したPython参考版。元提出版そのものではない |

元提出版のZIPは、展開して編集した内容で置き換えません。確認用ハッシュと説明を`original/`に置き、発展版の変更履歴から区別します。

## 三つの処理

| 処理 | 入力と出力 | 使用するモデル |
| --- | --- | --- |
| 顔検出 | 画像から顔の範囲と目・鼻・口の基準点を得る | YuNet |
| 特徴量と照合 | 向きと大きさをそろえた顔を128個の数へ変換し、登録特徴量との類似度を求める | SFace |
| 表情分類 | 切り出した顔から、8種類の表情ラベルへの出力を得る | FER+ |

顔検出だけでは誰かは分かりません。登録特徴量との比較を加えて初めて、登録者の候補を選べます。表情分類はその比較とは別に行います。

## 類似度としきい値

コサイン類似度は、二つのベクトルの内積をそれぞれの長さで割った値です。

\[
s=\frac{\sum_i a_i b_i}{\sqrt{\sum_i a_i^2}\sqrt{\sum_i b_i^2}}
\]

特徴量を単位長さへそろえると、内積だけで同じ値を計算できます。値の意味は「特徴量の向きがどの程度そろうか」で、本人である確率ではありません。

v1.1.0では1人につき最大12個の特徴量を保持し、その人の特徴量との類似度の最大値を使います。登録上限は100人です。複数サンプルを一つに平均していたv1.0.0の保存データは、平均特徴量を1サンプルとして読み込みます。平均する前の特徴量や登録写真の復元は行いません。

最も高い値がしきい値以上でも、次の候補との差が小さい場合は確定しません。同じ登録者が複数の顔の候補になる場合も、各顔を独立した本人として数えません。顔が小さい、品質情報を取得できない、撮影条件の点数が低い場合は判定を保留します。

OpenCVのチュートリアルには特定のデータセットで使った基準値がありますが、撮影条件や評価対象で適した値は変わります。アプリ内で値を変えられるのは、その変化を試すためです。

カメラ入力は異なるフレームを使って表示を安定化します。新規設定の既定は3フレームです。最初のフレームから一致候補を表示し、確認中の状態と確定した状態を分けます。同じ停止フレームを繰り返し処理して票を増やすことはしません。

時間的な多数決は、同じ顔を見続けた範囲で行います。多数決で安定しても、毎フレーム同じ誤りをしている可能性は残ります。

## 高速照合と多人数処理

高速照合では、YuNetによる検出とSFaceによる特徴量の計算を行います。FER+による表情分類は分析モードで必要になったときだけ準備・実行します。初回の読込量は照合用が実行ライブラリ込みで約50 MB、表情分類の追加が約35 MBです。

対応環境では、OffscreenCanvasを使うWorkerへ推論を分け、画面の操作と重い計算を分離します。利用できない環境は画面側の実行へ切り替え、使っている実行方式を表示します。処理中に別の画面・入力へ変わった場合は、以前の入力に対する結果を現在の画面へ反映しません。

高速照合は作業画像を縮小して全体を検出し、多人数・集合写真では大きな画像をタイルに分けて検出します。重なった検出枠はNMSでまとめます。一度に処理する上限は最大50顔で、検出数・処理数・上限による制限・処理時間を返します。

人数の上限を増やしても、画像内の顔に含まれる情報は増えません。遠く小さく写った顔に対し、名前を無理に割り当てることはしません。速度と精度の確認には、人数だけでなく画像の大きさ、顔の大きさ、端末、照明、登録画像との違いも必要です。

## 顔ごとの追跡と表示

顔ごとに追跡番号、現在の候補、確認回数、表情の平滑化、時系列、自己申告を分けます。画面内の位置だけでなく特徴量も使って前の顔と対応させ、各フレームで一つの顔を複数トラックへ割り当てません。

顔の交差や入れ替わりで対応が曖昧になる、候補が変わる、顔を見失う場合は、以前の名前・投票・表情・自己申告を引き継いで一致表示を確定しません。結果はその入力・そのフレームの照合として扱い、古い名前を使い回して更新が速くなったようには見せません。

複数人の照合結果は一覧で表示し、詳しい分析や動作確認は選んだ顔を対象にします。記録を有効にした場合は各顔を別の行として保存し、追跡番号で分けられるようにします。

## 写真・動画と顔の隠れ

本人照合と動作確認は別の結果です。動作確認は、選んだ顔を追いながら指示に対応した動きを確かめる実験です。通常のRGB画像を使い、実際の奥行きを測定するセンサーは使っていません。3Dの基準点を画像から推定する手法も、実深度の測定や生身の証明とは区別する必要があります。

写真や画面に表示した動画に対する耐性を評価したPADモデルは、この版には組み込んでいません。未評価の推測を「立体の顔だけを認める」機能としては表示しません。NISTによるRGB画像のPAD評価や関連資料は[参考資料](sources.md)を参照してください。

マスクやサングラスで見えない部分を生成して補う処理はありません。利用するSFaceと今回の入力条件で精度を保てる検証がなく、しきい値の緩和も行いません。見えている顔の情報で照合し、不十分な場合は保留します。

## ブラウザ版と参考Python版

ブラウザ版は静的なHTML・CSS・JavaScriptとしてGitHub Pagesへ配置します。ONNX Runtime Webと学習済みモデルを同じ公開元から読み込み、画像・特徴量を外部の推論APIへ送信しません。カメラへのアクセスは利用者が開始したときだけ行います。

公開用に調整したPython参考版は`local/`に収録しています。OpenCVの顔検出・照合とPythonの画面用APIを使い、同じPCの中で動作します。元提出版は別のZIPとして保持します。ブラウザ発展版とPython各版では前処理・実行環境・判定の条件が異なるため、結果の小数点以下までの一致は前提にしません。

ブラウザ版のZIPには学習済みモデルと実行ライブラリを同梱します。手元で動かす場合は、ファイルを直接開く方式ではなく、展開したフォルダーで`python3 tools/serve.py`を実行し、HTTPサーバーから配信します。

## 保存する内容

| 内容 | ブラウザ版の扱い |
| --- | --- |
| 入力した画像・カメラ映像 | 処理中だけ使用し、登録データやCSVへ保存しない |
| 登録名と複数の特徴量 | 既定ではメモリ内。端末への保存を選んだ場合だけブラウザへ保存 |
| 設定 | 端末への保存を選んだ場合だけ登録内容と一緒に保存 |
| 分析ログ | 記録を始めたときだけメモリへ追加し、必要な場合にCSVへ書き出す |
| ダウンロードしたCSV | ブラウザの外にある利用者のファイルとして扱う |

入力した名前はHTMLとして解釈させず、文字列として表示します。保存データを読む際には型・長さ・数値の範囲・特徴量の次元を検査し、不正な内容を登録情報として使わないようにします。

削除では、画面に見える登録者だけを消して関連記録を残す状態を避けます。ただし、既に保存したCSVなどのファイルを、アプリから後で回収することはできません。

## 分析教材の範囲

Colabの最初の例は、仕組みを追えるように用意した合成データです。`for`で条件を変え、`if`で受入・拒否を判定し、辞書で結果を集計します。合成データの値を、実際の人物・モデルの性能や学生の測定結果として紹介しません。

正解情報を別に持つ二者照合では、本人の比較と別人の比較に分けて誤り率を計算できます。一方、通常の利用ログにある「一致」「未登録」という判定は、正解情報そのものではありません。この区別を保って可視化します。

グラフは日本語の見出し・軸・凡例を使います。実測CSVでは、画像や特徴量を持ち込まずに、類似度や撮影条件を調べられます。名前を表示しなくても成立する分析では、氏名の列を使いません。

## 改良するとき

入力画像を固定して前処理の変更を比べ、その後に撮影条件を変えます。一度にモデル・しきい値・撮影条件をすべて変えると、何が結果を変えたか分かりにくくなります。

登録と確認に同じ画像を使うこと、正解ラベルを予測結果から作ること、連続フレームをすべて独立した人物数として数えることを避けます。比較するときは、人数・画像数・撮影回数・正解情報の作り方も結果と一緒に残します。

使用したモデルと実行ライブラリは[出典](sources.md)を参照してください。
