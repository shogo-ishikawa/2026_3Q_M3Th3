# FACEGATE ローカル版

学生作品の画面と、カメラでの顔照合・表情分類・分析機能を残したPython版です。画面はこのPCのブラウザで開き、計算もこのPCの中で行います。Pythonを使わずに試す場合は、プロジェクトのWeb版を利用してください。

## Windows 11で起動する

1. 配布ZIPを右クリックして「すべて展開」を選びます。ZIPを開いたまま起動しないでください。
2. [Python公式サイト](https://www.python.org/downloads/windows/)からPython 3.12をインストールします。最初の画面で **Add python.exe to PATH** を選びます。既にPython 3.10〜3.13があれば利用できます。
3. この `local` フォルダーの **`起動.bat`** または **`start.bat`** をダブルクリックします。
4. 初回は専用環境 `.venv` と必要なライブラリを準備します。黒い画面を閉じずに待ちます。Python本体のインストールや利用規約の承諾を自動実行する処理はありません。
5. 公開ZIPの3モデル（合計約74 MB）は `local` と同じ階層の `models-web` に同梱されています。SHA256が一致すればそのまま使います。ローカル版だけをコピーした場合など、モデルがないときは画面の「ダウンロード開始」で取得します。
6. 「ユーザー管理」から本人の同意を確認して登録し、「顔認証」または「分析モード」で試します。

アプリの画面を閉じると終了します。起動に失敗した場合は黒い画面のエラーを確認してください。依存ライブラリの準備に失敗した場合は通信環境を確認し、`start.bat` を実行し直します。モデル取得に失敗した場合は、画面のエラーと `download_log.txt` を確認します。

Windowsの実機とカメラでの最終確認は未実施です。Python 3.12・Linuxでは模擬エンジンによる起動、登録、照合、記録、削除とモデルの読込みを確認しています。配布時点の詳細はプロジェクトの検証記録を参照してください。

## Mac・Linux、または手動で起動する

Python 3.12を推奨します。ターミナルでこの `local` フォルダーへ移動して実行します。

```sh
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python main.py
```

WindowsのPowerShellで手動起動する場合は、環境の有効化の代わりに次のようにPythonを指定できます。

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe main.py
```

ローカル画面の接続先は `http://127.0.0.1:8765` が基本です。別のアプリが使っている場合は起動時に別のポートを選びます。画面に表示されたURLを使用してください。サーバーを外部公開する設定には変更しないでください。

## できること

| 画面 | 内容 |
| --- | --- |
| ホーム | モデルの準備、登録人数、最近の照合記録 |
| 顔認証 | 登録した特徴量との類似度を計算し、複数フレームで同じ結果が続いたら表示 |
| 分析モード | 8種類の表情ラベルのスコア、推移、明るさ・ピント・顔の向き、動作チャレンジ、自己申告との比較 |
| ユーザー管理 | カメラまたは写真から特徴量を登録し、登録者を削除 |
| アクセスログ | 照合の記録、分析レポート、確認用画像によるしきい値の評価 |
| 設定 | カメラ、しきい値、フレーム数、表示時間、ぼかし、保存データの削除 |

通常の顔照合と動作チャレンジは独立しています。動作チャレンジは顔の向きや表情の変化が指示に合うかを試す機能で、録画や画面提示に対する生体検知性能を保証するものではありません。表情の出力は画像の分類ラベルです。本人が申告した気持ちと比較できますが、本人の気持ちを直接測定した値ではありません。「表情ラベルの合成スコア」は便宜的な重み付き平均で、場の雰囲気や全員の心理状態を表す数値ではありません。

初期しきい値は学生作品の実験値に合わせて0.70です。別の条件で撮った確認用画像を使って調整してください。入退室の管理や重要な本人確認の判定には使わず、顔認識の仕組みと誤り方を調べる教材として利用します。

## 保存するデータと削除

顔写真は登録時に自動保存しません。照合用の特徴量128個、名前、同意日時、登録元などを `data/face_db.npz` と `data/face_db.json` に保存します。特徴量も本人と照合できる情報です。フォルダーごとの共有は避けてください。

照合記録は `data/access_log.csv`、分析モードとコマンド実行の記録は `logs/session_日時.csv` に保存します。レポートは `reports/`、コマンド画面のSキーによる画面保存は `screenshots/` に入ります。画面保存には顔画像が含まれる場合があります。

- **登録者を削除**すると、特徴量・名前・同意情報と、アクセスログや分析CSVの本人に関連する行を削除します。旧形式の自由文イベントは個人を確実に分けられないため、イベントだけの行をまとめて削除します。生成レポートと画面保存も個人別に分けられないため、全員分を削除します。画面ではこの範囲を確認してから実行します。
- **設定の「アプリが保存したデータをすべて削除」**では、登録者・設定・アクセスログ・分析CSV・生成レポート・画面保存を削除します。取得済みモデルは残します。
- 自分で用意した登録・確認用写真、指定した入力動画、アプリの外へコピーしたCSV・レポート・画面保存は削除対象に含みません。必要に応じて元の保存先から削除してください。

顔の映像・特徴量・記録を外部サービスへ送る処理はありません。モデルがない場合の取得と、Pythonライブラリを導入する通信は発生します。サーバーは127.0.0.1に限定し、別サイトからのAPI操作や別ホスト名での接続を拒否します。

## コマンドで実験する

```sh
python main.py download
python main.py register たろう --folder data/register/たろう
python main.py register はなこ --camera
python main.py list
python main.py delete たろう
python main.py run
python main.py run --source 比較用の動画.mp4
python main.py evaluate data/test
python main.py report logs/session_日時.csv
```

照合の評価では、登録と確認に同じ写真を使わず、`data/test/名前/` に登録者の確認用画像を、`data/test/_unknown/` に未登録者の画像を置きます。本人拒否、登録者の取り違え、未登録者の受入を数えます。入力データの人数と撮影条件を増やして比較し、同じ人物の連続フレームだけで精度を一般化しないでください。

登録者をコマンドで削除するときは、先にアプリの画面とリアルタイム実行を終了してください。起動中の画面から削除する場合は「ユーザー管理」を使います。

コマンドのリアルタイム画面ではQで終了、Cで動作チャレンジ、1〜8で気持ちの申告、+/−でしきい値調整、Bで未登録者のぼかし、Aでアバター、Sで画面保存を操作できます。

## モデルと依存関係

顔検出はYuNet、特徴量と照合はSFace、表情分類はFER+を使います。元のモデルを学習し直す機能ではありません。取得先とSHA256は `face_app/config.py` に固定しています。ネットワークが制限される場合は、同じファイルを別のPCで取得し「ファイルから取り込む」で指定できます。内容の不一致やGit LFSの案内ファイルは拒否します。

PythonライブラリはOpenCV、NumPy、Pillow、Matplotlibです。モデルとライブラリの出典・ライセンスはプロジェクトの第三者配布物一覧にまとめています。

## 構成とテスト

`main.py` が入口、`face_app/webapp.py` がローカルAPIとカメラ処理、`face_app/web/` が元作品を生かした画面です。`engine.py` は顔検出・特徴量・表情分類、`registry.py` はDB、`privacy.py` は記録を含む削除、`tracker.py` は追跡と多数決、`quality.py` は撮影条件の評価を担当します。

開発用の確認は次のとおりです。本物のモデルとカメラを使わず、模擬画像で処理と保存を検証します。

```sh
python -m pip install pytest
python -m pytest tests -q
```

テストで作成される `tests/_artifacts/`、保存データ、仮想環境は公開ソースと配布ZIPに含めません。モデルは取得先とハッシュを固定し、公開ZIPでは `models-web/` に同梱します。
